# 云端拍照任务实现与本机验收

基线 `main@62a7c59`，实施分支 `codex/cloud-capture-tasks`。本轮只做本地提交，不 push、不 SSH、不部署。四类拍照任务只上传图像，不做面诊、舌诊、安全帽或 PCB 推理。

## 1. 入口与资源关系

```mermaid
flowchart LR
  Cloud[云端：本轮 loopback mock] -->|HTTP 长轮询| Bridge[capture_cloud_bridge]
  Bridge -->|CaptureTask action| Executor[capture_task_executor]
  Executor -->|SpeakText 完成确认| TTS[现有唯一 TTS；本机 fake]
  Camera[已有原始 RGB] --> Executor
  Executor -->|robot：申请、续租、释放| Guard[motion_guard TaskHold]
  Executor -->|JPEG + SHA + 质量指标| Cloud
  Executor -->|feedback / result| Bridge
  Bridge -->|ack / events / heartbeat| Cloud
```

新增 `capture_task_interfaces` 和 `capture_task` 两包，独立于现有语音意图/执行模式；不导入 tongue_mode，不写 modes.yaml，不发布任何速度，不调用授权或复位服务。旧语音、舌苔、guard 源码保持基线不变。复制适配的少量工具在源码头注明来源。

执行器阶段：ACCEPTED → CHECK → HOLD（robot）→ ANNOUNCE → PREPARE → CAPTURE → QUALITY → UPLOAD → DONE_ANNOUNCE → UPLOADED；异常 FAILED，取消 CANCELLED。失败原因仅记录，不拿任意服务端文字播报；只播目录里的安全失败文本。

- 相机恰好一个发布者，接受 rgb8/bgr8/rgba8/bgra8，转换为 RGB；原图不缩放。准备结束才设采集窗口，同时检查接收时刻和同源 ROS 时间戳；接收龄必须为0–0.5秒；ROS帧龄为−0.05–0.5秒，允许设备时钟换算导致最多50ms超前，与舌苔模式一致（模块常量MAX_FUTURE_STAMP）。窗口前的帧仍拒绝。时限、网络退避、静止稳定窗口用 monotonic。
- 连拍间隔约 100 ms；默认选 Laplacian 方差最高帧。质检含亮度、清晰度、R/B 和宽高。warn 上报问题仍上传；fail 拒绝。PCB 模型默认输入 640×480，最小宽度为 640，与当前 Gemini 原始 RGB 匹配；不放大图像。
- SpeakText 的 `completed` 才能进入准备和采集。超时、取消与迟到接受只取消本任务的 goal，不调用全局语音取消。播报禁用词经 NFKC、忽略标点空白和格式字符后校验。
- bench 要求 `/cmd_vel` 零发布者；robot 要求唯一发布者名为 motion_guard，始终申请 TaskHold，并监测新鲜控制状态、owner/session、静止 odom、急停健康，0.5 秒静止稳定后才播报。租约每0.5秒续租、结束释放，迟到申请成功也释放。TaskHold 服务返回的 token 只在内存，不记录。
- robot 认可 DISARMED / ESTOP 的静止状态；**现有 guard 在 ESTOP/FAULT 拒绝 ACQUIRE**，此时任务返回 hold_failed。没有修改 guard、没有清除锁存。若检测中 authority 变成 FAULT/ARMED 或健康失效，立即失败。
- `/execution_mode/state active=true` 且接收龄不超过6.5秒时拒绝新任务，执行中出现新鲜active也中止。manager失联时舌苔模式6秒自行退出，6.5秒阈值留出清理余量；从未收到视为不活跃，解析失败按active处理且同样过期。robot 下同时争抢租约由现有原子 TaskHold 仲裁。ROS 拒绝 goal 没有 result transport，原因在 `/capture_task/result` 发布，bridge 在 ack 转述；接受后 HOLD 失败体现在最终 result，而非撤销 accepted ack。
- 失败通知使用独立 min(speech_timeout_sec,15秒) 时限，不受任务超时、安全/静止错误抑制；只播目录的fail_announce，关闭/外部取消/TTS本身失败时不补播。通知失败不改变原始结果，robot在通知结束后才释放租约。上传内部中止使用独立upload_cancel，不冒充外部取消。
- 上传单线程池、最大12 MiB、最多3次尝试；取消关闭 socket。上传已到云端的数据不能因取消撤回。SIGINT/SIGTERM 清理期间保持 ROS executor 运行，尽力取得自己租约的释放确认；崩溃时仍由 guard 租约超时保护。

## 2. 参数和存储

任务目录 `capture_task/config/tasks.yaml` 是四任务播报/准备/质检来源；`capture_task.yaml` 展示节点默认值；launch 提供常用参数。

| 参数 | 默认 / 约束 |
|---|---|
| cloud_url / robot_id | http://127.0.0.1:8090 / roscar-01；可用 CAPTURE_CLOUD_URL / CAPTURE_ROBOT_ID；地址允许/roscar等安全路径前缀 |
| poll_wait_sec | bridge默认1，整数0–20；CAPTURE_POLL_WAIT_SEC / launch透传，非法启动报错 |
| token_file | 空；可用 CAPTURE_TOKEN_FILE，文件须当前用户拥有且0600；CAPTURE_CLOUD_TOKEN 环境变量优先 |
| camera_topic / camera_profile | /camera/color/image_raw / raw_rgb_v1 |
| safety_profile | bench；接底盘由整机入口强制 robot |
| storage_dir / save_images | artifacts/capture-task / false |
| with_bridge | true；仅测 action 可设 false |
| with_ros_api | false；显式true追加只转发action的capture_api节点 |
| fake_tts / synthetic_camera | false；只允许 bench + localhost + 187/190隔离域 |
| hold_lease_sec | executor 参数默认3秒，合法1–10秒 |

执行器存 events.jsonl、每个已上传 capture_id 的 result.json（质量、字节数、SHA、回执，不含图像/token）。显式 save_images=true 只在整个任务成功后保存图像，取消/失败不保留本地 image.jpg。**mock 为检查协议会保存收到的图片**于 artifacts/capture-mock，均被 Git 忽略；测试后用户可自行清理这些隐私数据。

bridge执行器状态接收龄超过1.5秒即不可用：新拍照ack unavailable（先于busy检查），心跳unknown且camera_ok/tts_ok=false，bridge_state带executor_stale=true；恢复新鲜状态后自动恢复。执行模式消息与执行器统一使用6.5秒过期规则；各计时均为monotonic。

bridge单一HTTP worker：默认wait=1约1请求/秒，有待发事件用wait=0，GET的总时限与socket预算为实际wait+2秒；poll_wait_sec可配0–20整数。心跳目标间隔10秒，调大wait可能使事件、取消处理和心跳额外延迟最多wait秒；服务端新指令应立即唤起长轮询。feedback/result经256条有界outbox；断网重试期间不增长线程。

队列溢出会取消当前任务并淘汰最早待发送条目，因此长时间断网不能保证所有历史事件送达；重启也不持久恢复队列或去重缓存，正式云端需对账。完整10分钟 command_id 去重（按时间清理，不提前按条数淘汰）；任务ID应每次唯一。optional speak 只做协议校验，本轮返回 unsupported。

### 本机 usb_cam 0.8.1 时间戳修正

实测首次采集虽约14Hz，消息帧龄约0.95秒，因此被新鲜度门控拒绝。已安装的 `include/usb_cam/utils.hpp:get_epoch_time_shift_us()` 写成 `epoch_time.tv_usec / 1000.0`，使已经是微秒的字段被错误缩小，偏移会随进程启动的小数秒变化。未放宽帧龄，也未按接收时刻伪造曝光时间戳。

`build_capture_usb_cam.sh` 下载官方 ros-drivers/usb_cam 的0.8.1固定提交 `cb2ae6bc0a312de629f84fef933fb3e07dac1ef8`，只将该项改为 `epoch_time.tv_usec`，在 artifacts/capture-usb-cam 独立构建。源码、补丁构建物不进Git，不改 /opt/ros；本机入口发现有修正标记才加载overlay，若检测到已知问题且尚未修正会拒绝启动并给出命令。此修正仅用于本机 USB 联调，不改车上 Gemini 独立驱动。保护检查使用标准grep，不依赖rg；ROS action图查询失败也直接退出。CAPTURE_USB_CAM_HEADER / CAPTURE_USB_CAM_OVERLAY仅用于本机注入检查或选择修正overlay。

## 4. 车端接入准备（未部署）

`start_project.sh` 新增 WITH_CAPTURE_TASKS=false，start_c.sh 继承。

- true 要求 WITH_VOICE=true 和 VOICE_TTS_ENABLED=true，透传已有 enable_speech_action=true；不改现有语音包，不启动第二个真实 TTS。
- WITH_CHASSIS=true 强制 safety_profile=robot，要求用户显式设置 WITH_FOLLOWER=true，否则退出码2；该入口同时启动跟随器，运动仍受 MOTION_ENABLED 与逐次授权约束。不自动打开跟随，不增加第二个guard入口。

- 订阅原始RGB，不使用 C 绘制或矫正后的画面。不切换车上分辨率、不改640×480标定。正式端点/token/robot_id须配置；云端地址可带/roscar等前缀，去掉单个末尾斜杠，每段仅[A-Za-z0-9._~-]+，拒绝空段、点/双点段、百分号编码、凭据/query/fragment。mock可serve --prefix /roscar；默认loopback只是联调默认值。

本轮不启车端底盘、不停现有服务、不上Jetson；aarch64编译和独立域隔离验证须后续授权。
