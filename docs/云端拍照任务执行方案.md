## 0. 目标与边界

### 0.1 要做的

由云端下发指令，小车执行四类拍照任务：

```
云端下发指令 ──► 小车校验、接受 ──► 播报"即将进行××检测" ──► 倒计时准备 ──► 采集新鲜图像 ──► 上传云端 ──► 回报状态
```

| task_type | 中文名 | 说明 |
|---|---|---|
| `face` | 面诊检测 | 人正对相机，面部无遮挡 |
| `tongue` | 舌诊检测 | 人正对相机伸舌。**与现有语音舌苔模式 `tongue_mode` 是两套独立流程** |
| `helmet` | 安全帽检测 | 拍前方场景 |
| `pcb` | PCB 缺陷检测 | 电路板放在相机前，对清晰度要求最高 |

本轮只做两件事：

- 小车端的逻辑与接口；
- 一个模拟云端（mock cloud），用于联调。

云端推理不在本轮范围内。开发和测试都在**本机**完成：把 Gemini 相机从车上拔下，插到本机 USB 口，用本机 ROS 2 Humble 跑通全流程。

### 0.2 硬约束

1. **与现有语音控制逻辑互相独立。**
   - 云端任务不经过 ASR、`voice_command_router`、`execution_mode_manager`，也不写入 `modes.yaml`。
   - 原则上不改以下包：`offline_voice`、`voice_command_router`、`xfyun_speech`、`deepseek_ros2`、`execution_mode_manager`、`tongue_mode`、`motion_guard`。
   - 如果确实必须改，要在 WORKLOG 写明理由，并补跑对应的回归测试。
2. **只复用共享资源，不另起一套。**
   - 相机：只订阅已有的 `/camera/color/image_raw`。
   - 播报：只调用已有的 `/voice/speak`（SpeakText action），`status=completed` 才算播完。不另起 TTS。
   - 车辆静止：在车上通过 `/control/task_hold` 申请停车保持。
   - 不新建任何速度出口。**永不发布 `/cmd_vel`、不授权运动、不清急停。**
3. **遵守 AGENTS.md。**
   - 每次更新都写 WORKLOG.md。
   - 本机测试不能写成"实车验证"。x86_64 上的 Humble 也不能等同于 Jetson aarch64 上的验证。
   - 新增文档要登记到 README 索引。
   - 图片和凭据不入 Git。
   - 未经用户同意：不 push，不 SSH 小车，不改小车在线服务。
4. **本机仓库不是唯一副本。** 来源和回传方式见 §6.0，不要直接 push 到 GitHub 覆盖。

## 2. 总体架构

```
              ┌──────────────── 云端（本轮用 mock 代替）────────────────┐
              │ 指令队列   事件/心跳接收   图像接收（→推理，不在本轮范围）│
              └────▲──────────┬──────────────▲──────────────▲───────────┘
            长轮询取指令│  ack/事件 │         图像上传 │          心跳 │
              ┌──────┴──────────▼──────┐        │              │
              │ capture_cloud_bridge   │────────┼──────────────┘
              │ 网络 ↔ ROS（去重、过期、取消） │        │
              └──────────┬─────────────┘        │
                 CaptureTask action             │
              ┌──────────▼─────────────┐        │
              │ capture_task_executor  │────────┘
              │ 播报→准备→采集→质检→上传│
              └──┬───────────┬─────────┬┘
       /voice/speak│   /camera/color/  │/control/task_hold（仅 robot）
       (SpeakText) │   image_raw       │/control/state、/odom
           ▼               ▼           ▼
      现有唯一 TTS     现有相机    现有 motion_guard
   （本机用 fake_tts） （本机用 usb_cam）（本机不启动）
```

几项关键决定：

1. **执行器和桥接分成两个节点。**
   - 执行器（executor）只认 ROS action，不关心云端怎么下指令。不接云端时，可以直接用 `ros2 action send_goal` 测它。
   - 桥接（bridge）只管网络。以后换 WebSocket 或 MQTT，只改 bridge。
2. **v1 的传输用 HTTP 长轮询，由小车主动出站连接。** 理由：
   - 不需要公网入站，NAT 后面也能用；
   - 只用标准库，Jetson 上不加依赖；
   - 云端用 FastAPI 很容易实现，curl 就能调试；
   - 与 `tongue_mode/cloud.py` 风格一致。

   如果以后要更低延迟，可以在 bridge 里加一个 WebSocket 传输类（Jetson 已装 `websocket-client`），消息体不变。
3. **一次只执行一个任务。** 忙时直接拒绝并回报 `busy`，由云端重试。v1 不做本地排队。
4. **时效不依赖小车与云端对时。** 指令的有效期用 `ttl_sec`，从小车**收到指令的时刻**开始算。
5. **上传与推理解耦。** 上传接口只回执"已收到"。推理结果由云端自己处理；以后如果要小车播报结果，用 §3.4 预留的 `speak` 指令。

## 3. 接口定义（先固定，各部分可以并行开发）

### 3.1 新包 `capture_task_interfaces`（ament_cmake）

`action/CaptureTask.action`：

```
# One cloud-issued capture job. Never moves the vehicle.
string task_id        # 云端任务号，[A-Za-z0-9_-]{1,64}
string task_type      # face | tongue | helmet | pcb（必须在 tasks.yaml 中）
string source         # cloud | local_test
string params_json    # 可选，只接受白名单字段，见 3.3
float64 ttl_sec       # 从执行器收到 goal 起算的总时限，0 表示用任务默认值
---
string status         # uploaded | failed | rejected | cancelled
string detail
string capture_id
string upload_json    # 云端上传回执（已校验）
---
string phase          # 见 4.2
string detail
```

### 3.2 ROS 话题与服务

| 名称 | 类型 | 说明 |
|---|---|---|
| `/capture_task/run` | CaptureTask action | 由执行器提供。只有 bridge 和测试脚本作为客户端 |
| `/capture_task/state` | std_msgs/String（JSON） | 4 Hz 发布，形如 `{"active":true,"task_id":..,"task_type":..,"phase":..,"detail":..}`。风格同 `/tongue/state` |
| `/capture_task/result` | std_msgs/String（JSON） | 每个任务结束时发布一条：ids、尺寸、字节数、质检指标、回执。**不含图像** |
| `/capture_task/bridge_state` | std_msgs/String（JSON） | bridge 状态：`online`/`backoff`/`auth_failed`，最近一次轮询时间，当前 command_id |

### 3.4 云端协议 v0

写入 `docs/云端拍照任务接口协议.md`，这份文档同时交给云端团队。

- 基础地址 `CAPTURE_CLOUD_URL`。本机 mock 为 `http://127.0.0.1:8090`；车上地址待定（舌苔云端目前在 `172.19.128.171:8096`）。`robot_id` 默认 `roscar-01`。
- 鉴权用 `Authorization: Bearer <token>`。token 来自环境变量 `CAPTURE_CLOUD_TOKEN`，或权限为 0600 的私有文件。**不入库、不进日志**。
- 所有 JSON 用 UTF-8，响应体不超过 2 MB。

| 方法与路径 | 方向 | 说明 |
|---|---|---|
| `GET /v1/robots/{robot_id}/commands/next?wait=20` | 小车 → 云 | 长轮询：204 表示没有指令，200 返回一条指令（格式见下）。服务端最多挂起 `wait` 秒 |
| `POST /v1/robots/{robot_id}/commands/{command_id}/ack` | 小车 → 云 | `{"accepted":true/false,"reason":"busy|invalid|expired|voice_mode_active|hold_failed|..."}` |
| `POST /v1/robots/{robot_id}/tasks/{task_id}/events` | 小车 → 云 | `{"phase":..,"detail":..,"seq":n}`，seq 单调递增 |
| `POST /v1/tasks/{task_id}/images` | 小车 → 云 | body 为 `image/jpeg` 原始字节，不超过 12 MB。请求头：`X-Robot-Id`、`X-Task-Type`、`X-Capture-Id`、`X-Frame-Index`、`X-Capture-Time`（UTC ISO8601）、`X-Camera-Profile`、`X-Image-Sha256`、`X-Quality`（JSON：亮度、清晰度、R/B、宽高）。成功返回 200 `{"status":"received","task_id":..,"capture_id":..,"upload_id":..}` |
| `POST /v1/robots/{robot_id}/heartbeat` | 小车 → 云 | 每 10 秒一次：`{"state":"idle|busy","task_id":..,"camera_ok":..,"tts_ok":..,"version":..}` |

指令格式：

```json
{"command_id":"c-uuid","type":"capture","task_id":"t-uuid","task_type":"pcb",
 "params":{"announce":"..."},"ttl_sec":60}
{"command_id":"c-uuid","type":"cancel","task_id":"t-uuid"}
{"command_id":"c-uuid","type":"speak","text":"检测结果……"}   // v1 可选，见 §6 P3
```

语义：

- **去重**：10 分钟内重复的 `command_id`，直接 ack 原结果。
- **过期**：收到后超过 `ttl_sec` 还没开始执行的指令，拒绝并回 `expired`。
- **上传重传**：同一个 `capture_id` 可以重传，云端按 sha256 去重；返回 409 且 sha 相同时视为成功。
- **错误处理**：
  - 4xx（409 除外）不重试，任务直接失败；
  - 5xx 或网络错误按退避重试，最多 3 次，且不超过任务时限；
  - 401/403 使 bridge 进入 `auth_failed`，之后每 60 秒低频重试，不刷屏。

### 4.2 执行器流程与阶段（phase）

```
ACCEPTED → CHECK → (HOLD) → ANNOUNCE → PREPARE → CAPTURE → QUALITY → UPLOAD → DONE_ANNOUNCE → UPLOADED
      任一步失败 → FAILED（播报 fail_announce，播报失败不掩盖原错误）/ 取消 → CANCELLED
```

1. **接受 goal 的条件。** 以下任一不满足就 REJECT，并在 result 中写明原因：
   - 当前空闲；
   - `task_type` 已配置，`task_id` 格式合法；
   - `params_json` 只含白名单字段，且通过禁用词校验；
   - `/execution_mode/state` 不是 `active=true`。语音舌苔模式进行中时，拒绝原因为 `voice_mode_active`。
2. **CHECK。**
   - `camera_topic` 恰好有 1 个发布者；
   - `/voice/speak` 服务端已就绪；
   - `safety_profile=bench`（本机或不接底盘）：要求 `/cmd_vel` **没有发布者**；
   - `safety_profile=robot`：要求 `/cmd_vel` 恰好有 1 个发布者（guard）。
3. **HOLD**（仅在 robot 且 `require_hold` 为真时）。
   - 照搬 tongue 的流程：ACQUIRE；每 0.5 秒 RENEW；确认静止满 0.5 秒后开始监视；结束时一定 RELEASE。
   - ACQUIRE 失败（例如语音舌苔模式已经持有）时，报 `hold_failed`。
   - 静止校验参照 `TongueMode.verify_stationary`。其中 `authority_state` 只允许两种：未授权（DISARMED）或急停锁存。出现运动授权（ARMED 等）则判失败。
   - 也就是说，急停锁存时照常可以拍照。执行器永远不触碰授权或急停。
   - motion_guard 在急停锁存时是否允许 ACQUIRE，要读 `motion_guard/task_hold.py` 和 `node.py` 确认；不允许就如实报 `hold_failed`，不要改 guard。
4. **ANNOUNCE。**
   - SpeakText 必须返回 `completed` 才继续。
   - 取消任务时，同时取消自己的播报 goal。
   - 迟到的 accept 要立即取消，参照 `tongue_mode.speak` 中的 `cancel_late`。
5. **PREPARE。** 等待 `prepare_sec`，期间持续检查取消、时限和静止状态。
6. **CAPTURE。**
   - 只取**播报完成且准备结束之后**才收到的帧，同时要求 ROS 时间戳晚于采集开始时刻，帧龄不超过 `max_frame_age_sec`。
   - 连拍 `burst` 帧，间隔约 100 ms。
   - `rgb8/bgr8/rgba8/bgra8` 统一转成 RGB。cv_bridge 只在节点层使用。
7. **QUALITY。**
   - 计算亮度均值、清晰度、R/B 比、宽高，选清晰度最高的一帧。
   - `quality_policy=warn` 时照常上传，指标放进 `X-Quality`；`fail` 时不达标即失败。
   - 宽度低于 `min_width` 时，一律如实写入 detail，**不放大图像凑数**。
8. **UPLOAD。**
   - 在单独的线程池中执行，重试规则见 §3.4。
   - 回执必须回显相同的 `task_id` 和 `capture_id`。
   - 取消时立即关闭 socket（同 `CloudClient.cancel`）。
9. **记录。**
   - 写 `storage_dir/events.jsonl` 和 `<capture_id>/result.json`。
   - 图像默认**不落盘**（`save_images=false`），因为面部和舌象属于隐私数据。本机调试时可以显式开启。
10. **时间基准。**
    - 时限和新鲜度一律用 `time.monotonic()`。
    - ROS 时间戳只与同源的 ROS 时间比较，不能与 monotonic 相减（与 `tongue_mode/capture.py` 的注释一致）。

### 4.3 bridge 规则

- **主循环**（单线程）：
  1. 长轮询取指令；
  2. 用 `protocol.py` 解析；
  3. 去重、判过期；
  4. 发 goal，并以 goal 是否被接受为准立即 ack；
  5. 把 feedback 转发为 events；
  6. 任务结束时，把 result 作为最终 event 上报。
- **`cancel` 指令**：只取消 `task_id` 匹配的当前 goal。
- **断网**：按 1、2、4……最长 30 秒指数退避，状态发布到 `/capture_task/bridge_state`。**不要用语音播报断网。**
- **退出**（SIGINT/SIGTERM）：取消正在执行的 goal，尽量发出最终 event。
- 本机不开放任何监听端口。

### 4.4 模拟云端 `scripts/mock_capture_cloud.py`

- 用标准库的 `ThreadingHTTPServer` 完整实现 §3.4，默认只绑定 `127.0.0.1:8090`。
- 数据目录可配置，收到的图片和 JSON 按 task_id 分目录保存。
- 子命令：
  - `serve [--port --store --token]`：启动服务；
  - `send <face|tongue|helmet|pcb> [--announce ..] [--ttl ..]`：下发拍照指令；
  - `cancel <task_id>`：取消任务；
  - `speak <text>`：下发播报指令；
  - `status`：查看状态。
- `send`、`cancel`、`speak` 通过 `POST /admin/...` 把指令加入队列。
- 支持故障注入：`--fail-upload 500|409|401`、`--slow-upload 秒`、`--drop-poll`，用于测试重试和断线。
- 这份脚本同时作为**交给云端团队的参考实现**。

### 5.1 安装（需要 sudo；agent 没有权限时，请用户执行）

### 5.2 ROS 隔离（必须做）

本机和小车在同一个局域网，小车使用 182 域。本机每个终端都要设置：

```bash
source /opt/ros/humble/setup.bash

```

运行时测试沿用仓库约定：设置它们要求的固定隔离域（例如 186 或 187）加 `ROS_LOCALHOST_ONLY=1`，否则测试会拒绝运行。任何时候都不要用 182 域。

### 5.3 相机

把 Gemini Pro 的 USB 线从小车上拔下，插到本机 **USB3 口**，然后：

```bash
lsusb | grep -i 2bc5                 # 应看到 2bc5:0511（彩色 UVC），可能还有深度设备
v4l2-ctl --list-devices
v4l2-ctl -d /dev/videoN --list-formats-ext
ros2 run usb_cam usb_cam_node_exe --ros-args \
  -p video_device:=/dev/videoN -p image_width:=1920 -p image_height:=1080 \
  -p pixel_format:=mjpeg2rgb -p framerate:=15.0 -r image_raw:=/camera/color/image_raw
```

注意事项：

- **只用 1920×1080 或 2592×1944。** 避开会偏蓝的低分辨率模式。参数名以 `ros2 param list /usb_cam` 的实际输出为准。
- **权限问题。** 如果打不开 `/dev/video*`，先 `ls -l /dev/video*` 看属主和 ACL；必要时由用户执行 `sudo usermod -aG video smxvjv`，重新登录后生效。
- **验收标准。** `ros2 topic hz /camera/color/image_raw` 达到 10 Hz 以上；抽一帧保存，R/B 比在 0.8–1.25 之间。样张不入库。
- **备选方案。** 相机没到位或不稳定时，用静态图继续开发：

  ```bash
  ros2 run image_publisher image_publisher_node <样张.jpg> --ros-args -r image_raw:=/camera/color/image_raw
  ```
- 本机没有电脑自带摄像头可以兜底；手头有其他 UVC 摄像头也可以先用。

按 README 的约定，在仓库根目录编译，产物放在根目录的 `build/` `install/` `log/`，这三个目录已被 Git 忽略：

### 5.5 播报

## 8. 风险与待确认（不阻塞开发，写进实现文档的"待办"）

1. **车上分辨率。** 车上相机话题是 640×480，并且可能偏蓝；PCB 要求 `min_width: 1280`，车上达不到。
   - 如果要为拍照单独切换到高分辨率彩色模式，会影响 C 路线基于 640×480 的标定。
   - **本轮不改**，只如实上报质检指标，由用户决定。
2. **本机与车上的差异。** 本机 usb_cam 读到的 1920×1080 画面，与车上 astra_camera 驱动发布的画面在色彩、曝光和帧率上可能不同。本机结论只代表本机。
3. **云端未定项：**
   - 最终地址和是否用 HTTPS；
   - `robot_id`；
   - token 怎么下发；
   - 是否需要用 `speak` 回播结果；
   - 推理结果是否要回传小车。

   协议里都已预留，确定后只改配置。
4. **急停锁存时是否允许拍照。** 本方案默认允许，因为拍照不涉及运动。如果要禁止，改为在 CHECK 阶段读 `/control/state` 判断即可。
5. **x86_64 与 aarch64 的差异。** 纯 Python 部分基本不受影响，但 cv2、numpy 版本以 Jetson 实际版本为准。最终上车前，建议在 Jetson 隔离目录再跑一次运行时测试，需经用户同意。
