## 真实 ROS 集成场景

1. “舌苔检测”经过现有 router 进入通用 manager，取得 guard 保持，提示播放完成后取新图、上传 JPEG、校验结果、播报，并持续 READY。
2. 模式保持期间直接请求 FOLLOW/ARM、说“前进”，均不能绕过停车保持；auto_arm 也不重新移动。
3. 播报上次结果不增加上传次数。
4. 重拍生成新图、新 capture/request ID。
5. retake 保持空标签，不制造八项阴性；不重播前次成功冒充本次。
6. 相机断流时不上传提示前缓存图。
7. 云端 digest 不符时不拍照或播报正常判断。
8. 模拟提示音频播放失败时不继续捕获。
9. HTTP 等待中重拍，取消旧连接，只保存新请求结果。
10. HTTP 等待中退出，迟到响应不保存、不播报，车辆仍 IDLE。
11. 第二个模拟业务模式实现同一 RunMode 接口，等待舌苔模式完成清理后才进入；验证模块可独立整合。
12. manager 心跳停止时舌苔模式退出，释放停车保持，仍 IDLE。

最终模拟上传 8 次，保存 6 条有效协议结果；差额包括取消的请求。测试保留 ROS 真接口与实际任务节点，但 **RGB、音频播放、odom 和云端模型全部是模拟输入**。

## 本轮发现并修正

- manager 原字段名与 rclpy.Node 的只读属性 clients 冲突，改为 mode_clients；构建后运行验证通过。
- TTS/guard 退出时 context 已失效导致发布异常，增加有效性与销毁状态判断，并修正测试退出顺序。
- 旧控制测试将 ±0.16 m/s 当作越界，而当前 SafetyConfig 默认为 ±0.2；改为按实际配置生成越界测试，保留保护代码的原限速。
- 重拍时保持旧取消 Event 不再复用，取消 socket 清理后才允许新请求，避免迟到结果与线程积压。
- 增加 prompt action 迟到接受后的取消、播放进程启动竞态清理、唯一图像/速度发布者检查，以及源 ROS 时间戳与接收窗口双重检查。

## 没有验收的内容

本轮未 SSH Jetson 或 3090，没有安装板端依赖、同步/切换正式服务、运行大模型推理或启动车辆。没有验证实物 Astra 的近距离对焦、舌体像素尺寸、实际 ASR 转写、扬声器声学表现、实际车轮停稳和跨网段访问。

因此，本轮结论是“完整模式的软件流程与通用整合接口已实现并通过本机 ROS 验证”，不是“已经在小车落地”或“现场分类准确率达标”。

## 测试隔离事故与恢复

初始测试使用 `/home/ubuntu/.cache/roscar-humble-test/rootfs`。测试期间这个共享路径的 workspace 被绑定到原小车仓库，后续部分文件复制误写了源目录。发现后停止使用该路径，并恢复本任务可识别的误写。

6 个原有文件已恢复为最初读取快照中的逐字节内容，6 组误加路径移出源目录进入恢复备份；原项目其他正在进行的语音/控制改动保留，没有重置整个仓库。恢复记录位于舌象项目的 `ros_car_tongue_integration/source_recovery_20261004/recovery.json`。

最终验证改在单独命名的 `/home/ubuntu/.cache/tongue-mode-01a07fde-validation/rootfs` 中执行，复制前核实 workspace 为 ext4 根文件系统、没有嵌套绑定源目录。最终结果不采用事故后的共享路径失败日志。

原项目阅读期间也有其他修改，不能声称整个目录前后完全一致。后续测试必须使用专用目录并在写入前检查实际挂载，不复用其他任务的测试路径。
