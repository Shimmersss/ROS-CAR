# 云台跟随设计与串口协议草案

> 状态：设计草案，尚未实现。MCU 型号、舵机型号、pan 角来源（编码器或陀螺仪+零位开关）均未定。本文约定坐标系、数据流、云台与底盘的运动方法，以及 MCU 串口接口，供写 MCU 固件和 Jetson 节点时共同遵守。新链路应作为独立入口，默认关闭；在标定和实车验收完成前，不影响现有 A/B/C 感知和控制入口。

## 1. 总体思路

- **人的位置只估计一份，放在 `odom` 中。**云台和底盘都从这一份估计取数，各自独立控制。
- **云台负责“盯住”**：让人始终处于画面中心，并在车转弯时反向补偿。
- **底盘负责“跟上”**：根据人在车体坐标中的位置，保持跟随距离、对准方向。**底盘不读取、也不跟随云台角度。**
- 目标丢失时，底盘停车，云台单独去搜索；底盘不会追着云台的搜索动作转。
- 阿克曼底盘不能原地转向。人在车侧方又离得近时，由云台先盯住，底盘等人走到前方，或者边前进边对正。

## 2. 硬件与职责

```
Jetson ──USB 串口──► 云台 MCU（STM32/ESP32 等）
                       ├─ I²C: MPU6050 (0x68)        装在相机支架上，随俯仰一起动
                       ├─ I²C: AS5600 (0x36)         方案 E：pan 轴绝对编码器
                       ├─ GPIO: 霍尔/微动零位开关      方案 G：pan 轴零位
                       ├─ PWM: pan 舵机（360° 连续旋转，只控转速）
                       └─ PWM: tilt 舵机（180° 位置型）
```

- MCU 负责：高频读传感器、姿态解算、pan 角估计、舵机闭环、限位和超时保护、时间戳。
- Jetson 负责：人体检测、TF、人在 `odom` 中的估计、计算云台目标角、底盘控制。
- 舵机用独立 5–6 V 电源，与 MCU 共地；不要从 Jetson 或 MCU 的 5 V 取电。
- 设备名建议用 udev 固定为 `/dev/gimbal_mcu`。

## 3. 坐标系

### 3.1 坐标树

三维交互图见 [diagrams/云台坐标系3D.html](diagrams/云台坐标系3D.html)：车体按厂商 URDF 轮距和轴距建模，云台、相机、IMU 位置为示意值；可拖动 pan/tilt、移动人，并演示底盘纯追踪加云台几何指向。

```
map（可选，以后接 SLAM 时再加）
 └─ odom
     └─ base_footprint
         ├─ base_link                  厂商静态 TF，z +0.019 m，保持兼容
         └─ pan_link                   pan_joint：绕 z 轴转，角度来自 MCU
             └─ tilt_link              tilt_joint：绕 y 轴转，角度来自 IMU
                 ├─ imu_link           固定，安装角需标定
                 └─ camera_link        固定，需标定
                     └─ camera_color_optical_frame   相机驱动发布
```

### 3.2 各坐标系定义

所有坐标系均遵循 REP-103：x 向前、y 向左、z 向上；光学坐标系除外，见表。

| 坐标系 | 原点 | 轴向 | 静态/动态 | 数据来源 |
|---|---|---|---|---|
| `odom` | 底盘驱动启动或里程计复位那一刻，`base_footprint` 所在的地面点 | 当时车的前、左、上 | 相对 `base_footprint` 连续变化，会缓慢漂移，不跳变 | 底盘 `/odom` |
| `base_footprint` | 厂商 mini_akm URDF 的车体中心在地面的投影：后轴在 x≈−0.070 m，前轴在 x≈+0.074 m（轴距约 0.143 m，轮距约 0.16 m） | 车体前、左、上 | — | 沿用厂商定义，与厂商 `base_link`、`laser` 静态 TF 保持一致 |
| `pan_link` | pan 转轴与转盘上表面的交点 | z 沿 pan 转轴向上；pan=0 时 x 指向车头 | 动态，绕 z 转 `pan_rad` | 车体→转轴的平移卷尺量；角度来自 MCU |
| `tilt_link` | tilt 转轴中点 | y 沿 tilt 转轴向左；tilt=0 时 x 水平向前 | 动态，绕 y 转 `tilt_joint` | pan→tilt 的平移卷尺量；角度来自 IMU 换算 |
| `imu_link` | MPU6050 芯片 | 按芯片丝印 | 相对 `tilt_link` 固定 | 平移卷尺量，旋转按第 13 节标定 |
| `camera_link` | 相机驱动定义的根坐标系 | 前、左、上 | 相对 `tilt_link` 固定 | 用地面 ChArUco 板，在多组云台姿态下标定 |
| `camera_color_optical_frame` | 彩色相机光心 | z 沿光轴向前、x 向右、y 向下 | 相对 `camera_link` 固定 | 相机驱动 |

关节和量的符号约定：

| 量 | 定义 | 正方向 |
|---|---|---|
| `pan_rad` / `pan_joint` | 云台相对**车体**的水平转角，正前方为 0 | 从上往下看逆时针（向左）为正 |
| `imu_pitch_rad` | IMU x 轴相对**重力水平面**的俯仰 | 低头为正（绕 +y 左轴，右手定则） |
| `tilt_joint` | `imu_pitch − base_pitch − imu_pitch_offset` | 低头为正 |
| `imu_roll_rad` | IMU 相对重力的横滚 | 绕 +x 前轴，右手定则 |
| `up_xyz` | IMU 坐标系下指向天的单位向量 | — |

- MPU6050 安装约定：tilt 为 0 时，x 轴大致沿相机光轴向前、y 向左、z 向上。实际安装偏差由 Jetson 端标定的 `imu_link→camera_link` 固定旋转修正，MCU 不处理。
- pan 软件限位默认 ±170°，防止线缆绞断。限位在 MCU 内执行，不依赖 Jetson。
- 人的位置是 `odom` 里的一个点，用消息发布，不作为 TF 坐标系发布。

### 3.3 TF 发布归属（防止冲突）

| 变换 | 发布者 |
|---|---|
| `map → odom` | SLAM（以后再加） |
| `odom → base_footprint` | 项目里的 `odom_tf` 桥，数据来自底盘 `/odom`；以后接 EKF 时改由 EKF 发布，并关闭此桥 |
| `base_footprint → base_link` | 厂商静态 TF |
| `base_footprint → pan_link → tilt_link → {imu_link, camera_link}` | `robot_state_publisher`（URDF + `/gimbal/joint_states`） |
| `camera_link → camera_color_optical_frame` | 相机驱动 |

启用云台链路时，**以下三处必须关闭**，否则 `camera_link` 或光学坐标系会同时有两个父坐标系，TF 树会出错：

1. 厂商 `robot_mode_description` 中的 `base_to_camera` 静态 TF（`base_footprint → camera_link`）。
2. 感知 `camera_mount.yaml` / `gemini_mount.yaml` 中的 `publish_mount_tf`（`base_link → camera_link`）。
3. 导航 `sensors.yaml` 的 `camera` 项（`base_footprint → camera_color_optical_frame`），保持 `confirmed: false`。

## 4. 数据流

```
Gemini RGB-D 30 Hz（时间戳=拍摄时刻）
  │
  ▼
YOLO + ByteTrack（云台转动补偿） + 深度测距
  │  人在光学坐标系中的位置，附带 observation_stamp
  ▼
人位置估计器 ◄── TF：按 observation_stamp 查询 odom ← camera_color_optical_frame
  │  在 odom 中做恒速卡尔曼滤波和门控
  │  输出位置、速度、协方差、真实测量年龄（约 30 Hz，可随时预测）
  ├──────────────────────────────┐
  ▼                              ▼
云台控制器 50 Hz              底盘跟随器 20 Hz
  预测“现在+时延”时人的位置      预测“现在”时人的位置
  换算到 base_footprint          换算到 base_footprint
  算 pan / tilt 目标             纯追踪：v, ω
  + 车体转速前馈                 │
  + 画面中心微调                 ▼
  │                         /control/cmd_vel_request
  ▼                              │
/gimbal/command                motion_guard（唯一出口）
  │                              │
  ▼                              ▼
gimbal_bridge ──串口──► MCU    /cmd_vel ──► 底盘 STM32

MCU STATUS 200 Hz ─► gimbal_bridge ─► /gimbal/joint_states ─► robot_state_publisher ─► TF
底盘 /odom ─► odom_tf ─► TF（odom → base_footprint）
```

要点：

- **所有坐标换算都按“数据对应的时刻”查询 TF**，不使用最新值去对应旧数据。检测结果用拍摄时刻；云台和底盘指令用当前时刻。
- **卡尔曼滤波必须在 `odom` 中做。**如果仍在光学坐标系里滤波，云台一转，人看起来就在跳，会被深度门控拒绝。门控规则和“被拒测量不刷新测量时间”的约定保持不变，只是改在 `odom` 中判断。
- **跟踪器转动补偿**：ByteTrack 默认相机静止。相邻两帧之间相机的旋转 R 可以从 TF 查到，用 H = K·R·K⁻¹ 把上一帧的检测框预测位置平移到当前帧，再做匹配。
- 人位置估计的输出复用 `TargetState`（`header.frame_id=odom`）不够用，因为它缺少速度和协方差字段。实现时需要扩展该消息或新增一个消息。原有光学坐标系的 `target_state` 保持不变。

### 4.1 位置来源优先级

C 路线现有三种位置输出，云台链路沿用，各自用途不同：

| 输出 | 参考点 | 主要依据 | 在本链路中的用途 |
|---|---|---|---|
| `target_state`（source=`yolo`） | 检测框中心射线上的躯干代表点 | 躯干区域的真实深度 | **底盘跟随和云台指向的主输入**：上身深度最容易取到，1.9 m 处噪声约为厘米级 |
| `target_state_unified`（source=`yolo_unified`） | 双踝中点在地面上的投影 | 按以下顺序取用：双踝深度 → 躯干深度投影到脚踝射线 → 单目双踝与地面求交；多个来源同时有效时做保守融合 | 人在地面上的位置、显示和跌倒判断；底盘只在主输入失效时才把它作为后备 |
| `target_state_ground`（source=`yolo_ground`） | 脚下接地点 | 只用单目射线与地面求交 | 独立对照，不进入控制 |

- **有深度时，单目地面定位仍然在用，只是排在后面**：统一定位中，双踝没有深度（比如穿深色裤子）时会退到“躯干深度投影”或“单目双踝”。
- 单目方式对俯仰误差很敏感：相机高 0.25 m、距离 1.9 m 时，俯仰每差 1°，距离约差 26 cm；相机高 0.45 m 时约 15 cm。所以它的可靠程度取决于 IMU 俯仰的精度和相机的安装高度。
- 后两种输出都要求安装外参和地面平面确认完成，否则保持 NOT_READY。现在它们使用 `base_link` 坐标系，接入云台链路后要改为在 `odom` 中输出，并按观测时刻查询 TF。

### 4.2 深色裤子

黑色或深色布料会吸收深度相机的近红外光，导致腿部深度大面积缺失。已有录像中，497 个有 ID 的样本只有 107 个取到了双踝深度。应对办法按优先级排列：

1. **控制不依赖腿部深度**：底盘和云台用躯干深度（第 4.1 节的主输入）。上衣通常比裤子容易测，取躯干区域内有效像素的中位数，也能容忍零散空洞。
2. **脚部改用单目几何**：统一定位在双踝没有深度时，自动退到“躯干深度投影”和“单目双踝”。前提是：跟随距离足够让双脚入画（见第 6.2 节，暂定 1.9 m）、IMU 俯仰准确、相机尽量装高。
3. **调整相机参数（待实测）**：适当提高红外曝光、增益或激光功率，可能会改善深色布料的回光。Gemini Pro 具体支持哪些参数，需要用 SDK 查询后再做对比测试：分别穿深色和浅色裤子，统计腿部深度的有效比例。
4. **不建议用空洞填补算法**：用周围深度去补洞，很容易把背景的深度填到人身上，造成测距跳变。只允许在小空洞内、沿同一表面做填补。
5. **上身也是深色时**：躯干深度同样会稀疏。此时只能降低对深度的依赖，主要靠检测框和单目几何，并且放宽卡尔曼测量噪声。这种情况要单独录像验证。
6. **确认 SDK 的空洞填补已关闭**：如果开着，它会把背景深度补到裤子上，造成测距跳变。需要核对采集代码中的设置。

### 4.3 深度视场比彩色窄

按出厂内参计算：彩色 640×480 的视场为水平 70.5°、竖直 55.9°；深度 640×400 为水平 67.5°、竖直 **45.3°**。

- 相机横放、离地 0.25 m 时，整个人进入画面所需的距离：彩色约 1.63 m，深度约 **2.14 m**（均按占用 90% 视场计算）。
- 所以在跟随距离 1.9 m 时，脚在彩色画面里看得到，可以用单目几何；但脚落在深度视场之外（脚的俯角约 −7.9°，深度画面下边缘约 −7.2°）。即使穿浅色裤子，统一定位的“双踝深度”来源在这个距离也基本用不上，实际依赖“躯干深度投影”和“单目双踝”。

### 4.4 用深度在线拟合地面（已初步实现，默认关闭）

> 实现与参数见 [方案C统一定位与三维姿态](方案C统一定位与三维姿态.md) 的“深度地面拟合与动态重力”一节。以下为设计说明。


- 做法：对深度画面中的地板点用 RANSAC 拟合平面，每帧得到地面在光学坐标系中的方程，也就是相机相对地面的高度、俯仰和横滚。
- 好处一：用这个平面代替“标定 + IMU”推算出的地面，去和脚踝射线求交。平面和射线在同一帧、同一个相机坐标系里，俯仰误差会被抵消；单目定位的误差只剩平面拟合误差和脚踝像素误差。
- 好处二：可以在线检查 IMU 俯仰和地面确认参数是否一致，车走到斜坡上也能发现。
- 定位：它只提供地面平面，**不取代单目定位**。脚的位置仍然来自脚踝像素射线；腿部没有深度时，这仍是主要后备。各来源的优先级为：双踝深度 → 躯干深度投影 → 单目双踝与“实测平面”求交 → 单目双踝与“标定平面”求交。
- 限制：反光瓷砖、深色或无纹理地面可能拟合失败，失败时退回标定平面。按项目约定，它只能作为一项新证据，经过验证后才能参与地面确认，不能自动把 `ground_plane_confirmed` 置为真。
- 横放时，深度画面下边缘只到 −7.2°，大约要 2 m 以外才看得到地板；第 14 节的“相机竖装”能明显扩大地板的覆盖范围。

### 4.5 跌倒判断与云台（已初步处理，默认关闭）

> 已实现 `pose3d_up_source=floor|tf`：逐帧重力、横滚门控、相机转动重置二维下坠参考；默认 `static` 保持原行为。尚未实现像素下坠的旋转补偿，转动期间二维跌倒只会漏报、不会误报，由三维规则补足。


现有规则：三维依据不足（没有可靠的肩髋膝深度，或 `pose3d_gravity_confirmed=false`）时，退回二维规则（`basis=2d`）；`pose_upright_confirmed=false` 时，最多只报“疑似”，不确认跌倒。云台会破坏这两条规则的前提，接入时必须处理：

- **重力方向变成动态**：`pose.yaml` 里的 `pose3d_up_*` 是光学坐标系下固定的向上方向。云台俯仰和横滚一变，这个方向就跟着变。接入云台后，必须改为按每帧观测时刻，从 TF（IMU 换算得到的 tilt 关节角）求出重力方向，不能再用固定值。
- **“相机直立”变成逐帧条件**：二维规则用“躯干相对图像竖直方向的角度”判断姿态，前提是相机没有横滚。`pose_upright_confirmed` 应改为逐帧判断：IMU 横滚在容差内（初值 ±3°）才算直立，否则这一帧的二维结论标为未知。
- **云台转动会制造假的“下坠”**：二维跌倒规则看的是“肩髋中心在图像中下降超过框高 25%”。云台向上抬头时，人在画面中会整体下移，可能被误判为下坠。处理办法有两种：一是云台转速超过阈值时，暂停二维跌倒计时，但不清空历史；二是把下坠量换算到重力方向的角度或米制坐标后再判断。三维规则本身就在重力坐标下计算，不受这一影响。

## 5. 云台运动方法

### 5.1 几何指向（主控制）

1. 取人位置估计在“现在 + 云台时延”时刻的预测值，换算到 `base_footprint`，得到点 p。
2. 记 pan 转轴在 `base_footprint` 中的位置为 a，tilt 转轴离地高度为 h，人身高为 H（初值 1.7 m）：

   ```
   pan_target  = atan2(p.y − a.y, p.x − a.x)
   d_h         = hypot(p.x − a.x, p.y − a.y)
   θ_head      = atan2(H − h, d_h)            头顶仰角
   θ_feet      = atan2(h, d_h)                脚的俯角
   tilt_target = −(θ_head − θ_feet) / 2       画面中心对准头和脚的中间（低头为正，负值为抬头）
   ```

   tilt 不对准躯干，而是让**头和脚都进画面**。原因：按 Gemini 出厂内参，彩色相机竖直视场只有 55.9°，对准躯干时，近处的人脚会出画面，统一定位和跌倒判断就失去依据。相机离地 0.25 m、人在 1.9 m 处时，`tilt_target` 约为抬头 15°。跟随时距离变化不大，tilt 基本保持不动，符合第 5.3 节“俯仰尽量固定”的原则。

3. 如果相机光轴经过 pan 转轴，即相机没有横向偏置，上式就能准确对中。相机横向偏置为 e 时，会产生约 e/d_h 的角度偏差：比如偏 3 cm、距离 1.5 m 时约 1.1°。这部分由下面的画面微调消除。

### 5.2 画面中心微调（辅助）

- 角度误差：`e_pan = −atan((u − cx)/fx)`，`e_tilt = atan((v − cy)/fy)`，其中 (u, v) 是检测框中心的像素坐标。
- 用一个慢速 PI 环叠加到几何目标上（积分限幅），用来吸收标定误差和相机偏置。几何指向负责快速响应，PI 环只修正剩余偏差。
- 死区：|误差| < 3° 时不调整，避免云台来回抖动。

### 5.3 前馈、限速与限位

- **前馈**：`pan_rate_ff = 人绕 pan 轴的角速度（由估计器的速度算出） − 车体偏航角速度`。车体一转，云台立刻反向转，不必等下一帧图像。
- **限速**：转动会造成运动模糊，模糊长度约为 ω × 曝光时间 × fx 个像素。按曝光 20 ms、fx = 452 估算，60°/s 时约 9.5 px，30°/s 时约 4.7 px。初值建议：跟踪时 ≤ 45°/s，搜索扫描时 ≤ 30°/s；实测后再调。
- **限位**：目标角超出 ±170° 时，在限位处停住并置标志。水平视场 70.5°，停在 ±170° 时最远仍能看到约 205°，所以车正后方没有盲区。此时人已经在车后方，由底盘转向解决；但阿克曼车需要前进才能转向，所以通常是等人走回前方。
- **回卷滞回**：人从 +175° 走到 −175° 时，云台不能直接越过正后方，只能反向转约 340°；按 45°/s 计算要 7–8 s，期间人会丢失。所以只要人还在画面里（与当前朝向相差不超过半视场减 5°，约 30°），云台就停在限位处，靠画面偏移继续跟踪；超出后才反向回卷。
- **俯仰**：尽量保持固定，例如水平或略低头。地面定位和三维姿态都对俯仰最敏感，固定俯仰时误差最小。只有人离得太近、头或脚出画面时才调整俯仰。

## 6. 底盘跟随方法（纯追踪，阿克曼）

### 6.1 输入

人位置估计在“现在”时刻的预测值，换算到 `base_footprint`，得到 (x, y)，以及真实测量年龄 τ。纯追踪以后轴中点为参考，所以先平移到后轴：`x_r = x + 0.070`（后轴在 `base_footprint` 中的 x 坐标为 −0.070 m，以实车量取为准）。

### 6.2 计算

```
d     = hypot(x_r, y)                       与后轴中点的水平距离
α     = atan2(y, x_r)                       人相对车头的方位角，左为正
κ     = 2·sin(α) / d                        纯追踪曲率，以人为预瞄点
κ     = clip(κ, −1/R_min, +1/R_min)         R_min 为实测最小转弯半径
v     = clip(k_v·(d − d*), 0, v_max) · max(0, cos α)
ω     = v·κ
```

- `d*` 是跟随距离，从后轴中点算起，**暂定 1.9 m**。原因：人身高按 1.7 m 计，竖直视场 55.9°，相机到人至少约 1.65–1.75 m 才能让整个人入画（留 10% 余量）；再加上后轴到相机的距离，折算到后轴约 1.9 m。这个距离下深度测量仍然可用：已有录像中人在 1.8–2.9 m 范围内，510 个有人体框的样本有 488 个取到了身体深度；但绝对精度还没测，待做 1/2/3 m 卷尺对比。如果以后只需要跟随、不需要看脚，可以再缩短。
- `cos α` 项：人偏到侧方时自动减速，避免大角度高速转弯。
- **v = 0 时 ω 必须为 0。**阿克曼车不能原地转向。厂商驱动把 `angular.z` 原样下发，由下位机换算成转向，具体方式需在实车上核对。
- **不倒车。**沿用现有约定。
- 加速度限制：|dv/dt| ≤ 0.3 m/s²，曲率变化率也要限制，防止转向舵机猛打。初值待实测。
- `v_max` 沿用现有 0.15 m/s 的上限，验收通过后再逐步放宽。

### 6.3 不动的条件

满足以下任一条件时，输出 v = 0、ω = 0：

- 人位置估计无效，或真实测量年龄 τ > 0.3 s。只靠预测时，底盘最多维持 0.3 s；云台可以维持更久。
- TF 查询失败：pan 角无效、MCU 数据过期、odom 中断等。
- `d ≤ d*`：已经到达跟随距离。
- |α| > 60°，且 d < d* + 0.5 m：人在侧方且离得近，阿克曼转不过去。此时停车，由云台盯住，等人走到前方。
- `motion_guard` 不在 `ARMED` 状态，或者触发了故障锁存。这一层由 guard 自己执行，跟随器不需要绕过它。

## 7. 状态机与失效处理

| 状态 | 进入条件 | 云台 | 底盘 |
|---|---|---|---|
| INIT | 上电；IMU 校准中、方案 G 未回零、TF 不完整 | HOLD 在 0 位；方案 G 执行 HOME | 停 |
| SEARCH | 没有锁定目标 | 保持正前方，或在 ±90° 内慢速扫描（≤ 30°/s） | 停 |
| TRACK | 已锁定目标，估计有效且新鲜 | 几何指向 + 画面微调 + 前馈 | 纯追踪 |
| LOST_SHORT | 丢失 ≤ 1 s | 指向预测位置 | 测量年龄超过 0.3 s 后减速停车 |
| LOST | 丢失 > 1 s | 回到最后已知方位，然后慢速扫描 | 停 |
| FAULT | pan 无效、MCU 超时、TF 过期、CRC 错误率过高 | **HOLD**；不做纯画面闭环，因为不知道 pan 角就无法保证限位 | 停（guard 同时锁存） |

- 从 LOST 回到 TRACK，沿用现有锁定规则：必须重新锁定，或者经 ReID 身份确认，不能自动接到画面里的另一个人身上。
- 进入 FAULT 后，即使数据恢复也不会自动继续运动，需要人工重新授权。这与 `motion_guard` 现有的故障锁存规则一致。

## 9. pan 角来源：两种方案

### 方案 E：AS5600 磁编码器（推荐）

- 径向磁铁（直径 6 mm，径向充磁）固定在 pan 转轴末端，AS5600 芯片固定在底座、正对磁铁，间距 0.5–3 mm。
- 读 `RAW ANGLE`（寄存器 0x0C–0x0D，12 位，0.088°/LSB）和 `STATUS`（0x0B：MD 检测到磁铁、ML 太弱、MH 太强）。
- 计算：`pan = wrap_pi(dir × (raw − zero_raw) × 2π / 4096) / gear_ratio`
  - `zero_raw` 由 CONFIG 命令“以当前位置为零”写入并保存到 Flash。
  - `dir` 取 ±1，使左转为正；磁铁直接装在输出轴上时 `gear_ratio = 1`。
- 因为 pan 限位在 ±170° 以内，单圈绝对角已经足够，上电不需要回零，读到就是当前角度。
- 有效条件：MD=1 且 ML=0、MH=0，否则 `pan_valid=0` 并上报 EVENT。
- `pan_rate` 由角度差分后低通得到。

### 方案 G：MPU6050 陀螺积分 + 零位开关

- 零位开关：在底座正前方装 A3144 霍尔开关，云台转盘上贴一块小磁铁，经过正前方时触发；也可以用微动开关。
- 云台绕竖直轴的转速 = IMU 测得的总转速 − 车体转速：

  ```
  ω_vertical = up_xyz · gyro_xyz          （云台在空间里绕竖直轴的转速）
  pan_rate   = ω_vertical − base_yaw_rate （减去车体转速，base_yaw_rate 由 Jetson 在 COMMAND 中下发）
  pan       += pan_rate × dt
  ```

- 回零：开关边沿处把 `pan` 置 0。霍尔开关有回差，左转和右转经过时的触发位置不同，所以两个方向各自标定一个边沿偏移量，置零时用对应方向的偏移。
- 置零前，把当时的累计 `pan` 值通过 EVENT 上报。这个值就是两次回零之间的漂移量，可用来评估误差。
- 有效条件：上电后已回零过一次（`homed=1`），并且最近 100 ms 内收到过有效的 `base_yaw_rate`，否则 `pan_valid=0`。
- `ms_since_home` 超过阈值（初值 60 s，待实测漂移后再定）时，Jetson 降级：云台仍按画面闭环居中，但不再把相机坐标换算到车体或 `odom`。

两种方案的数据帧完全相同，由 `pan_source` 字段区分；以后从 G 换成 E，Jetson 端不用改。

## 10. 俯仰（tilt）

- 测量：MPU6050 姿态解算（Mahony 或互补滤波，500–1000 Hz），得到相对重力的 `imu_pitch`/`imu_roll`。加速度计在车加速时会把这部分加速度误当成重力，滤波时陀螺权重应占主导。
- 控制：内环按舵机标定表把目标角换算成 PWM 脉宽；外环用 IMU 俯仰做慢速积分修正（带宽约 2–5 Hz），补偿舵机回差和负载造成的误差。
- MPU6050 建议设置：DLPF 42 Hz、陀螺量程 ±500 dps、加速度量程 ±2 g。上电后保持静止 2 s 做陀螺零偏校准，期间 `imu_calibrating=1`。
- Jetson 端换算 tilt 关节角：`tilt_joint = imu_pitch − base_pitch − imu_pitch_offset`。平地上 `base_pitch ≈ 0`，可取底盘 IMU 的值；`imu_pitch_offset` 为标定得到的安装偏差。

## 11. 帧格式

- 串口参数：460800 bps，8N1，所有多字节字段均为**小端**，`float` 为 IEEE-754 单精度。
- 状态帧 69 字节 × 200 Hz ≈ 13.8 KB/s，占用 460800 bps 带宽的约 30%。115200 bps 不够用。

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 2 | 帧头 `0xA5 0x5A` |
| 2 | 1 | 版本 `0x01` |
| 3 | 1 | 类型 |
| 4 | 1 | 序号 `seq`（每类型各自循环 0–255） |
| 5 | 2 | 载荷长度 `len`（uint16，上限 128） |
| 7 | len | 载荷 |
| 7+len | 2 | CRC16 |

CRC16-CCITT-FALSE（多项式 0x1021，初值 0xFFFF，不反射，无异或输出），范围为从版本字节到载荷末尾：

```c
uint16_t crc16_ccitt(const uint8_t *p, uint16_t n) {
    uint16_t crc = 0xFFFF;
    while (n--) {
        crc ^= (uint16_t)(*p++) << 8;
        for (int i = 0; i < 8; ++i)
            crc = (crc & 0x8000) ? (crc << 1) ^ 0x1021 : crc << 1;
    }
    return crc;
}
```

校验值：对 ASCII 字符串 `123456789` 计算应得 `0x29B1`。MCU 端用结构体收发时必须按 1 字节对齐打包（`__attribute__((packed))`），否则编译器插入的填充字节会让帧长对不上。

收端解析：搜索帧头，读 `len`；如果 `len` 超出上限，或 CRC 不对，就丢掉第一个字节后重新搜索，同时累计错误计数。不要因为一帧出错就清空整个缓冲区。

| 类型 | 方向 | 名称 | 频率 |
|---|---|---|---|
| 0x01 | MCU→Jetson | STATUS | 200 Hz |
| 0x02 | Jetson→MCU | COMMAND | 50 Hz |
| 0x03 | Jetson→MCU | SYNC_REQ | 1 Hz |
| 0x04 | MCU→Jetson | SYNC_RESP | 应答 |
| 0x05 | Jetson→MCU | CONFIG | 按需 |
| 0x06 | MCU→Jetson | ACK | 应答 CONFIG |
| 0x07 | MCU→Jetson | EVENT | 事件触发 |

### 11.1 STATUS（0x01，载荷 60 字节）

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | uint32 | `t_us` | **传感器采样时刻**的 MCU 微秒计数（约 71 分钟回绕一次，由 Jetson 展开），不是发送时刻 |
| 4 | uint8 | `pan_source` | 0 无，1 编码器（方案 E），2 陀螺+零位（方案 G） |
| 5 | uint8 | `flags` | 见下表 |
| 6 | uint8 | `last_cmd_seq` | 最近一次执行的 COMMAND 序号 |
| 7 | uint8 | `fault` | 0 正常；非 0 为故障码 |
| 8 | float | `pan_rad` | |
| 12 | float | `pan_rate_radps` | |
| 16 | float | `imu_pitch_rad` | |
| 20 | float | `imu_roll_rad` | |
| 24 | float[3] | `gyro_xyz` | IMU 坐标系，rad/s，已扣零偏 |
| 36 | float[3] | `up_xyz` | IMU 坐标系，单位向量 |
| 48 | uint16 | `encoder_raw` | 0–4095；方案 G 填 0xFFFF |
| 50 | uint16 | `tilt_servo_us` | 当前 tilt 脉宽 |
| 52 | int16 | `pan_servo_cmd` | pan 转速指令，−1000…1000 |
| 54 | uint16 | 保留 | 0 |
| 56 | uint32 | `ms_since_home` | 方案 G 距上次回零的毫秒数；从未回零或方案 E 时填 0xFFFFFFFF |

`flags` 位定义：

| 位 | 含义 |
|---|---|
| 0 | `pan_valid`：pan 角可信 |
| 1 | `homed`：方案 G 已回零 |
| 2 | `magnet_ok`：方案 E 磁铁状态正常 |
| 3 | `imu_ok` |
| 4 | `imu_calibrating` |
| 5 | `cmd_timeout`：COMMAND 超时，已进入保持状态 |
| 6 | `pan_limit`：已到达软限位 |
| 7 | `servos_enabled` |

### 11.2 COMMAND（0x02，载荷 28 字节）

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | uint8 | `mode` | 0 DISABLE，1 HOLD，2 POSITION，3 RATE，4 HOME |
| 1 | uint8 | 保留 | 0 |
| 2 | uint16 | 保留 | 0 |
| 4 | float | `pan_target_rad` | POSITION 模式下的目标角，相对车体 |
| 8 | float | `tilt_target_rad` | 相对重力的 IMU 俯仰目标 |
| 12 | float | `pan_rate_ff_radps` | 前馈转速：POSITION 模式叠加在位置环上，RATE 模式直接作为转速指令 |
| 16 | float | `base_yaw_rate_radps` | 车体实测偏航角速度，供方案 G 使用；未知时填 NaN |
| 20 | float | `max_pan_rate_radps` | 转速上限，防止运动模糊 |
| 24 | float | `max_tilt_rate_radps` | |

各模式：

- **DISABLE**：pan 转速置 0，tilt 舵机停止输出 PWM（舵机断开，可能会因重力下垂）。
- **HOLD**：pan 转速置 0，tilt 保持当前角度。
- **POSITION**：pan 和 tilt 都闭环到目标角。
- **RATE**：pan 按给定转速转，tilt 闭环到目标角。
- **HOME**：方案 G 慢速转向零位开关并回零，完成后进入 HOLD；方案 E 直接回到 0 位。

`pan_valid=0` 时，MCU 拒绝 POSITION 模式，按 HOLD 处理。

**超时保护**：MCU 连续 300 ms 没有收到 CRC 正确的 COMMAND，就自动进入 HOLD 并置 `cmd_timeout=1`；之后收到新的有效 COMMAND 才恢复。**连续旋转舵机在任何异常情况下都必须先停转。**

### 11.3 时间同步（0x03 / 0x04）

- SYNC_REQ 载荷：`uint32 token`。
- SYNC_RESP 载荷：`uint32 token, uint32 t_rx_us, uint32 t_tx_us`，分别为 MCU 收到请求和发出应答的时刻。
- Jetson 端记录请求的发送时刻 T1 和应答的接收时刻 T4，计算：
  - 往返时间 `RTT = (T4 − T1) − (t_tx − t_rx)`
  - 时钟偏差 `offset = (t_rx + t_tx)/2 − (T1 + T4)/2`
- 在 10 s 窗口内只采用 RTT 最小的几组样本，对偏差做线性拟合，以吸收两边晶振频率的差异。
- 换算：STATUS 的 `t_us` 加上偏差即为 ROS 时间，用作 `joint_states.header.stamp`。USB 串口延迟通常为 1–4 ms，用最小 RTT 筛选后，残余误差预计在 1 ms 以内，需实测确认。

### 11.4 CONFIG（0x05）/ ACK（0x06）

- CONFIG 载荷：`uint8 key, float value`。
- ACK 载荷：`uint8 acked_type, uint8 acked_seq, uint8 result`，`result` 为 0 表示成功，非 0 表示拒绝或失败。

| key | 作用 | value |
|---|---|---|
| 1 | 以当前位置为 pan 零位（方案 E） | 忽略 |
| 2 | pan 软限位 | rad，默认 2.967（170°） |
| 3 | tilt 下限 | rad |
| 4 | tilt 上限 | rad |
| 5 | 陀螺零偏重新校准（云台须静止） | 忽略 |
| 6 | 当前配置写入 Flash | 忽略 |
| 7 | 方案 G 左转回零边沿偏移 | rad |
| 8 | 方案 G 右转回零边沿偏移 | rad |

### 11.5 EVENT（0x07）

- 载荷：`uint32 t_us, uint8 event, float value`。

| event | 含义 | value |
|---|---|---|
| 1 | 回零边沿触发 | 置零前的累计 pan，即本轮漂移量 |
| 2 | 磁铁丢失或强度异常 | AS5600 STATUS 寄存器值 |
| 3 | IMU 故障 | 错误码 |
| 4 | 到达软限位 | 当前 pan |
| 5 | COMMAND 超时 | 距上一次有效指令的毫秒数 |

## 12. Jetson 端节点与话题（待实现）

| 节点 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `gimbal_bridge` | 串口；`/gimbal/command` | `/gimbal/joint_states`、`/gimbal/imu`、`/gimbal/status` | 负责时间同步、CRC 校验、超时判断；pan 无效时停发 `pan_joint` |
| `robot_state_publisher` | URDF；`/gimbal/joint_states` | TF | 生成车体 → pan → tilt → 相机/IMU 的变换链 |
| 人位置估计器 | 光学系检测结果；TF | 人在 `odom` 中的位置、速度、协方差、测量年龄 | 恒速卡尔曼滤波与门控都在 `odom` 中做 |
| 云台控制器 | 人位置估计；TF；`/gimbal/status` | `/gimbal/command` | 第 5 节，50 Hz |
| 底盘跟随器 | 人位置估计；TF | `/control/cmd_vel_request` | 第 6 节，20 Hz；替代现有基于光学系偏角的 `person_follower` |
| `motion_guard` | `/control/cmd_vel_request`；雷达 | `/cmd_vel` | 现有节点，仍是唯一速度出口 |

- `/gimbal/joint_states` 中两个关节的时间戳，都用换算成 ROS 时间后的 MCU 采样时刻。
- `/gimbal/imu` 使用 `imu_link` 坐标系，只填角速度和加速度方向；`orientation_covariance[0] = -1`，表示不提供姿态。
- 以下情况停发 `pan_joint`：`pan_valid=0`、数据超过 50 ms 未更新、或 CRC 错误率过高。这样相机到车体的 TF 查不到，车体和 `odom` 下的目标位置自动失效，与现有“缺 TF 即无效”的处理一致。
- 云台指令走独立的话题和串口，不经过 `motion_guard`，也不进入 `/cmd_vel`。

|---|---|---|
| 编码器线性与零位（E） | 云台每转 30° 用量角器或 ChArUco PnP 对照一次 | 全程误差 ≤ 0.5° |
| 陀螺漂移（G） | 云台和车都静止 5 分钟，记录 pan 变化 | 记录实测值，作为回零间隔阈值的依据 |
| 回零重复性（G） | 左转、右转各经过零位 10 次，看 EVENT 上报的漂移和边沿角 | 边沿标准差 ≤ 0.5° |
| IMU 到相机的安装旋转 | 标定板平放在地上，在 ≥ 5 组俯仰姿态下，对比 IMU 的 `up` 方向和 PnP 算出的板面法线，用 Kabsch 方法求固定旋转 | 残差 ≤ 0.5° |
| 云台运动学 | 标定板平放在地上，云台在 ≥ 6 组不同 pan/tilt 姿态下各拍一次，联合求解 `tilt_link→camera_link` 固定变换和 pan 零位；pan、tilt 转轴位置先用卷尺量出初值 | 各姿态算出的板位置，相互差 ≤ 1 cm，板面法线夹角 ≤ 0.5° |
| 最小转弯半径与 `angular.z` 换算 | 低速打满方向绕圈，量轨迹半径；对比下发的 v/ω 与里程计回传 | 得到 `R_min`，并确认下位机对 `angular.z` 的换算方式 |
| 时间同步与延迟 | 云台匀速转动时，对比 ChArUco 板在画面中的方位与回传的 pan 角 | 求出时间差，残余 ≤ 5 ms |
| 超时停转 | 拔掉 Jetson 端串口，或停止发送 COMMAND | pan 在 300 ms 内停转，并收到 `cmd_timeout` 和 EVENT 5 |
| 限位 | 下发超过 ±170° 的目标角 | 停在限位处，置 `pan_limit=1` |

系统级验收（云台和底盘全部接通后）：

| 项目 | 方法 | 通过标准（初值） |
|---|---|---|
| 云台盯人 | 车静止，人在 1–3 m 处左右走动 | 人体中心在画面中的角误差，中位数 ≤ 3°，丢帧率另行记录 |
| 转弯补偿 | 人站定，车低速转弯 | 人在画面中的偏移峰值 ≤ 5°，且不丢失目标 |
| 侧方等待 | 人站在车侧方 1 m 处 | 底盘不动，云台盯住；人走到前方后底盘才起步 |
| 目标丢失 | 人走出视野，或被遮挡 | 测量年龄超过 0.3 s 后底盘减速停车，云台指向预测方向 |
| 故障注入 | 停止 MCU 回传；拔掉串口 | TF 失效，底盘停车，guard 锁存故障；云台在 300 ms 内进入 HOLD |
| 搜索不带动底盘 | 处于 SEARCH 或 LOST 状态时云台扫描 | 全程 `/cmd_vel` 为零 |
