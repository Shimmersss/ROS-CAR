# 2026-10-15 WSL 模拟云端拍照联调

## 结论与验证范围

使用 MeatShell 的 `5060wsl (easytier)` 作为模拟云端，按面诊 → 舌诊 → 安全帽 → PCB 顺序下发真实拍照任务。四项均收到 command ACK、阶段事件、JPEG 和合法上传回执。用户确认四类准备及完成播报“都听到了，正常”。

本轮按用户要求只验证采集、上传和播报，没有摆齐对应实物，不运行诊断/安全帽/PCB 推理。查看回传图片，当前画面是天花板；不代表获得了可用于这些业务的面部、舌体或实物画面。

## 实际链路

```text
WSL 参考云端下发 capture 命令
    → 车端 capture_cloud_bridge 轮询、ACK
    → capture_task_executor /capture_task/run
    → 复用唯一 motion_guard 的 TaskHold 与新鲜静止回传
    → 唯一 Matcha/Vocos 播报完成确认
    → 准备时间后的新鲜 Gemini 原始 RGB
    → 选帧、质检、JPEG 上传
    → WSL 存图并返回 SHA-256 回执
    → 完成播报、释放租约、云端 UPLOADED 结果
```

- WSL 管理入口：MeatShell `5060wsl (easytier)`，SSH 地址 10.126.126.2；独立目录 `/root/roscar-cloud-trial-20261015`，未修改该机已有项目工作区。
- 参考云端绑定 WSL 的 192.168.31.172:18090，使用本仓库 MockCloud HTTP v0 实现，启用临时 Bearer 鉴权和“拒绝未下发 task_id”检查。
- 小车直接访问 WSL 的 18090 端口超时；没有修改路由器/防火墙，改由 WSL 发起受限 SSH 反向隧道。小车访问 `http://127.0.0.1:18090`，实际 HTTP 处理和 JPEG 文件保存都在 WSL。
- 临时隧道密钥只允许监听小车 127.0.0.1:18090，禁止 shell；测试结束已移除临时授权、公私钥和两端 Bearer 凭据。凭据与照片不提交 Git。
- 车端独立临时服务 `roscar-capture-cloud-trial.service`，`safety_profile=robot / with_bridge=true / with_ros_api=false / fake_tts=false / synthetic_camera=false / save_images=false`。复用现有相机、播报及 guard，未启动第二个 TTS 或速度出口，未修改原开机入口。
- 运动关闭覆盖保持不变，未切换旧的语音急停配置，不把本次测试作为 KWS/急停验证。

## 四项结果

| 任务 | 命令 / 最终结果 | JPEG 尺寸 | JPEG 字节数 | 质检提示 |
|---|---|---|---:|---|
| 面诊 | accepted / uploaded | 640×480 | 37606 | 无 |
| 舌诊 | accepted / uploaded | 640×480 | 37771 | 无 |
| 安全帽 | accepted / uploaded | 640×480 | 37623 | 无 |
| PCB | accepted / uploaded | 640×480 | 37577 | width_below_minimum |

每项使用目录默认播报、准备时间、候选帧数及 JPEG 质量 95：面诊 3 秒/3 帧、舌诊 2 秒/3 帧、安全帽 1 秒/1 帧、PCB 3 秒/5 帧，最终各上传一张最佳帧。四张 JPEG 的 SHA-256 与 WSL 接收回执一致，WSL 和本机均能正常解码；四张哈希互不相同。

四项均经过 `HOLD → ANNOUNCE → PREPARE → CAPTURE → QUALITY → UPLOAD → DONE_ANNOUNCE → UPLOADED`。准备与完成播报由真实 SpeakText action 确认，用户另行确认实际可听。观察到 8 次 SPEAKING→IDLE，符合每任务准备/完成各一次。

PCB 的目录 `min_width=1280`，实际原始 RGB 只有 640 像素宽。默认 `quality_policy=warn`，所以成功上传并返回 `detail=width_below_minimum`。本轮没有放宽质量策略、放大图像或把此结果称作 PCB 业务画质验收；若改为 fail 策略，此分辨率会被质检拒绝。
