# 执行模式模块接口与合并约定

## 1. 通用约定

每个模式实现 `execution_mode_interfaces/action/RunMode`，提供独立 action 名称，例如 `/modes/tongue/run`、`/modes/patrol/run`。manager 从 modes.yaml 读取 id、action 和语音意图，不包含舌象模型或特定业务分支。

RunMode goal 的字段为 `mode_id/session_id/request_id`。一个 goal 表示完整模式会话，不是单次识别；初次流程完成后 action 仍活动，feedback.phase=READY。退出通过 action cancel 和带 session_id 的 EXIT 控制请求完成。最终 result.status 为 exited/cancelled/failed，并含 detail 与可选 last_result_json。

业务阶段通过 feedback 的 phase/detail/result_json 发布。READY 表示等待模式内下一操作；其余阶段由模块自己命名。manager 收到反馈更新 `/execution_mode/state`，持有期间向 `/execution_mode/heartbeat` 发布相同 mode_id/session_id，约 4 Hz。

## 2. 模式控制

- 外部控制只发 `/execution_mode/request` 的 ModeCommand，不直接启动模块 action，以保证一个模式所有者。
- ENTER 进入/切换，EXIT 退出；模块自己的命令由 manager 转发到 `/execution_mode/control`。
- 同一模式重复 ENTER 不重复开启会话。切换不同模式时先取消当前 action，等它最终返回后再发新 goal。
- 模块必须核对 mode_id/session_id；只处理本会话控制，并拒绝过期消息。
- request_id 去重；业务上传/采集另外使用独立 capture/request ID。
- 模块要检查 manager 心跳失效并退出；不得因为 manager 消失就长期执行动作。

未来词表例子：

```yaml
modes:
  - id: tongue
    action: /modes/tongue/run
    enter: [舌苔检测, 进入舌苔检测模式]
    retake: [重新拍摄]
    repeat: [播报上次结果]
    exit: [退出舌苔检测]
  - id: patrol
    action: /modes/patrol/run
    enter: [巡逻模式]
    exit: [退出巡逻模式]
    commands:
      NEXT_POINT: [下一个巡逻点]
common_exit: [退出当前模式, 取消当前任务]
```

这只是第二模块接入示例，不代表巡逻功能已经实现。commands 支持模式自定义大写操作，不需要在 manager 增加特定业务判断。语音短语不能重复，停止/急停等词不允许被模式抢占；普通讨论不做子串触发。

## 3. 共享资源

相机、ASR、TTS 和 guard 在整车只运行一套。新增模块订阅已有相机，语音统一先进入 router，再进 manager，避免多个节点各自订阅原 ASR 后抢话。

需要保持车辆静止的模块通过 `/control/task_hold` 获取 lease。ACQUIRE 原子停车并 IDLE，RENEW 需要 token，RELEASE/超时均保持 IDLE。持有时拒绝 ARM 和非 IDLE 模式切换，STOP 不受阻。不要为每个模式创建新的 `/cmd_vel` 出口。

需要拍摄前提示或其他顺序保证时使用 `/voice/speak` 的 SpeakText action，只有 status=completed 才继续。旧 `/voice/tts_text` 可用于不依赖完成确认的通知，不能把发布消息当作实际播放成功。

模式退出时取消自己的未完成播报和网络请求、释放自己的租约、清空会话可重播缓存。任何延迟结果都要先核对当前 generation/session，再保存或发声。

## 4. 多分支开发与合并顺序

1. 先把本分支的通用接口和接入层作为共享基线审查并合入整合分支。
2. 其他模式从相同基线创建独立分支，各自只新增业务包、测试和自己的文档。
3. 词表是预期的共享编辑点：合并时保留各 mode 条目，并运行 Catalog 冲突/保留词校验。
4. 不让每个模式都复制修改 voice_command_router、offline_voice、motion_guard 或各自再实现一套 manager。
5. 合并一个新模式后增加两方向串行切换测试、忙时退出、资源释放、停止优先级与旧功能回归。
6. 整合分支验证后通过 PR 合入最新 main，不直接覆盖其他工作目录的未提交文件。

如果其他模式已经修改这些共享文件，应按接口行为手工整合；不要整文件拷贝覆盖。舌苔业务包不依赖 JEV/Ollama 聊天实验，后续语言模型只负责提出可验证的模式命令，不能绕过 manager 和 guard。
