# C 统一定位与三维姿态增强

更新：2026-10-04。状态：本机软件实现；验证结果见文末。所有安装/重力/地面确认仍默认关闭，没有连接或部署小车。参数是初始规则，不能视为现场精度承诺。

## 输入与输出

C 启动时增加 `unified_localizer`，直接读取带真实关节深度的 `/perception/person_states`，使用观测时刻的 base←optical TF。它与原单目节点并列，原 `/perception/target_state` 的框中心射线代表点及 B 接口保持原含义。统一输出为：

| 话题 | 类型 | 含义 |
|---|---|---|
| `/perception/person_positions` | PersonGroundArray | 所有当前轨迹的统一接地点、来源、条件误差估计、有效位和原因 |
| `/perception/target_state_unified` | TargetState | 已锁定轨迹的统一接地点；source=`yolo_unified`，frame=`base_link` |
| `/perception/position_markers` | MarkerArray | 接地点与条件误差范围；失效、消失、断流时删除 |

统一参考点是**双踝中点向已确认地面的垂直投影**。X 前、Y 左、Z 为配置的地面高度；距离 hypot(X,Y)，偏角 atan2(Y,X)。它不是人体质心，也不是旧的光学框中心点。没有将二者直接混入同一滤波或改接运动消费者。

PersonState 新增 `body_depth_valid/body_depth_m/body_depth_source`，传递当前融合的躯体代表深度观测；无效为 NaN，不发布保持/预测深度，也不将其写入缺失关节。接口定义改变后需要重建消息包及消费者。融合关闭的对照路径使用当帧接受测量后的原区域滤波结果，来源标记 `legacy_regions_filtered`。

## 近远来源与切换

1. **depth_ankles**：两踝都有真实有效配准深度时，反投影所得关节变换到 base，检查接近踝高度平面和双踝一致性，再取中点的地面投影。
2. **depth_body_projection**：踝深度缺失时，使用至少两个一致的肩髋真实深度，或当前人体区域融合深度，将两条可见踝射线投到该深度，再进行平面/一致性检查。这是带较大不确定性的身体深度近似，**不是测得的踝关节**，不会补入 keypoints_3d。
3. **mono_ankles**：没有可用深度时，复用双踝射线与已确认踝高度平面的交点。禁止框底回退。个体身高先验不进入统一输出，因为它不是同一组脚部观测；原独立单目接口仍保留受限先验能力。

原测距现在也参与统一位置计算：把当帧躯体深度从框中心射线转换到可见肩髋中心射线，再变换到base坐标。双踝可见且各来源一致时，为同一轨迹记录“躯体中心到双踝中点”的水平偏移，连续3次一致后才使用，最多保留8组观测。只在站立、肩髋可见且几何合理时使用；坐蹲、跌倒、关系变化、断流或新epoch都会清除。它不是个体身高先验，也不经ReID转移。

脚短暂被挡住时，`body_contact` 使用**当帧躯体深度**和此前确认的对应关系估计脚下位置。对应关系默认最多保留0.75秒，误差随时间增长；不能在脚始终不可见时凭空建立关系。当前帧学到的关系不会用于验证同一帧自身。原光学TargetState话题保留作兼容与对照，不将其滤波坐标再次混入新滤波。

换算为同一脚下参考点之后，真实双踝、单目双踝、映射后的躯体观测通过协方差交集方式融合（`fused_contact`）。这些观测共享像素、深度或标定，不能当独立证据简单叠加精度：采用等权精度平均，融合误差不小于最佳来源的误差，并增加来源分歧项。各来源相差超过0.6米、与地面冲突或超出误差上限时拒绝。method和detail列出实际参与来源及躯体映射年龄。

新轨迹或全部来源被替换时需要连续3次确认；仍有共同的新鲜来源时保持连续。例如深度与单目一起工作后深度消失，当前单目仍有效，不再重等3帧。脚消失前映射后的躯体观测已加入融合时，也可以短时继续使用当前躯体观测。没有任何有效当前观测时立即失效，不用旧坐标保持。

时间上的位移门限为 0.25 m + 2 m/s × 真实观测间隔。跳变先拒绝；超过 0.5 s 无接受测量后允许以 3 次一致新观测重新建立位置，期间不发布旧坐标。断流、倒退时间、缺失轨迹和 epoch 更换都会重建确认。按轨迹独立维护状态，最多 128 个当前人、帧记录不无限累积。统一定位不做位置预测，所发有效位置均来自当前采集帧。

`std_m` 是条件误差估计，综合初始深度噪声、躯体投影误差、双踝间距、像素/踝高度误差、短时躯体映射误差，以及随距离增长的安装角误差；并非实测统计精度或可靠概率。默认深度噪声 0.06 m、身体投影误差 0.25 m、安装位置误差 0.10 m、角误差 1°。超过 `max_std_m`（默认 1 m）拒绝。配置见 camera_mount.yaml/gemini_mount.yaml 中 `/perception/unified_localizer` 的 `unified_*` 参数。

`unified_depth_max_m=3.0` 是基于用户所述有效范围的初始上限，可按测量修改。它不是对 Gemini 所有模式的硬件规格宣称；远距离是否可用还受脚部可见性、地平线、像素误差和平面假设限制，不保证 12 m 可用。

**边界：**建立接地点或更新躯体对应关系需要双踝可见。只有近期已确认对应关系、当前躯体深度和站立证据都有效时，才允许短时无脚定位；从开始就只拍到上半身，或关系已经过期，统一位置仍可无效。楼梯、斜坡、跳跃、脚悬空、躺卧/跌倒等情况不满足正常接地假设，不应将接地点估计当真值。

启用身份锁定恢复时，统一目标同时检查新鲜真实 `yolo` TRACKING 状态；身份未确认只保留全体人员的独立几何显示，不输出有效锁定目标。释放后无选中目标；不迁移 ReID 身高先验或旧轨迹滤波。

## 三维姿态与跌倒

Pose 节点直接使用真实采样并通过关联/跳变检查的三维关节。未改变 COCO17 的关节定义，不利用单目接地点补出全身三维骨架。

- 需要有效双肩双髋，检查躯干长度、肩/髋宽、两侧长度一致性，拒绝明显背景或分离表面。深度融合增加了同样的合理性检查，使肩髋沿 Z 倾斜的真实躯干能够通过；肩 3 m / 髋 5 m 之类的分离表面仍拒绝。
- 用肩中心→髋中心轴与已确认重力方向计算角度。站立/坐蹲再要求双膝深度，检查腿长与大腿相对重力方向；默认大腿角度超过 45°区分坐蹲。缺膝深度则降级二维。混合或明显矛盾姿态输出未知，不强制分类。
- 三维横卧要求躯干角超过原 60°阈值，且肩髋中心距已确认地面不超过 0.65 m；高位弯腰不按低位躺卧处理。
- 从持续稳定站立/坐蹲开始，1 s 内出现明显转横与中心下降超过 0.30 m，进入疑似；低位横卧持续 1 s 后确认。三维规则不要求二维人体框横宽，因此支持躯干向镜头方向倾倒的几何证据。
- 为支持连续旋转动作，时序规则保留最近稳定姿态的基线，允许中间倾斜/未知帧，但仅在原 1 s 窗口内有效。缺关键点、异常几何、断流、倒退时间或 epoch 变化不补报跌倒。
- 静态躺卧不报动态跌倒；缓慢躺下不满足快速变化条件。确认跌倒后持续站立 2 s 才解除。三维确认的事件需三维站立证据恢复，避免向镜头躺卧的人在二维上看似直立而被错误清除。二维时序每帧持续运行，三维米制时序单独保存，不互相搬用像素/米的下降量。深度缺失不再清空二维基线或候选；三维深度间隔在0.35秒内时暂停其候选计时，恢复时扣除缺失时间。超过期限只清空三维候选，二维继续。已确认事件有独立记录，不因深度消失而清除。

`person.detail` 与视频叠加标注 `basis=3d`、`basis=2d` 或 `basis=invalid3d`。没有可靠三维关节或重力未确认时走二维原规则；完整但解剖关系异常的三维证据当前帧输出未知，二维历史仍独立更新。可靠三维显示人体直立或中心仍处高位时，会否决透视造成的二维跌倒候选。深度缺失仍为 NaN。二维确定跌倒仍受原 `pose_upright_confirmed` 控制，三维确定跌倒必须同时确认重力和地面。

## 深度地面拟合与动态重力（2026-10-08，默认关闭）

为云台相机准备，设计背景见 [云台跟随设计与串口协议](云台跟随设计与串口协议.md) 第 4.4–4.5 节。所有新开关默认关闭，默认配置下 C 的输出与原来一致。

**地面拟合**（`floor_plane.py`，pose 节点参数 `floor_fit_enabled`）：

- 在已配准深度图的下部（`floor_roi_top_fraction` 以下）按步长采样，排除人体框（外扩 10 px），RANSAC 拟合平面。一半假设用局部邻域取点，云台抬头、地板只占采样点约 15–20% 时也能稳定采到地面；候选平面的法向必须与预期向上方向相差不超过 35°，否则先行剔除（排除墙面）。
- 精拟合用残差中位绝对偏差自适应收紧内点阈值（5 mm–2 cm），避免墙脚一侧的点把平面拉斜。
- 有效条件：内点 ≥300、占比 ≥0.10、残差 RMS ≤1.5 cm、平面内两个主方向的分布标准差都 ≥0.2 m（地板条太窄时法向定不准，宁可判无效）、相机高度 0.05–2.5 m。连续 3 帧一致（法向差 ≤2°、高度差 ≤3 cm）且无断流、时间不倒退，才标记为 `stable`。
- 发布 `/perception/floor_plane`（`person_interfaces/FloorPlane`），header 与彩色帧完全相同，包含向上法向量、相机离地高度、俯仰、横滚、内点数和残差。它只是证据，**不会**把任何 `*_confirmed` 置为真。

**统一定位使用实测地面**（`unified_localizer` 参数 `floor_plane_enabled`）：只采用与人体状态时间戳完全相同的稳定地面，把双踝像素射线与该平面（抬高踝高）在同一光学坐标系里求交，再经 TF 转到 base。来源记为 `mono_ankles_floor`，**替代**而不是叠加标定平面上的 `mono_ankles`（两者共享同一对踝像素）。安装俯仰误差不再按距离放大；若实测平面与已确认的地面高度相差超过 `unified_ankle_plane_tolerance_m`，不使用实测地面并在 detail 中写明。外参与地面确认仍是前提。

**跌倒规则的动态重力**（`pose3d_up_source`）：

| 取值 | 重力方向与相机高度来源 |
|---|---|
| `static`（默认） | 固定的 `pose3d_up_*` 与 `pose3d_camera_height_m`，行为与原来一致 |
| `floor` | 本帧稳定的地面拟合；要求 `floor_fit_enabled=true` |
| `tf` | 观测时刻 `gravity_frame`（默认 `base_footprint`，云台 IMU 驱动的 TF）到光学坐标系的变换 |

- 本帧拿不到重力时，三维退回二维（`basis=2d`、detail 含 `gravity=unavailable`），不复用旧值；三维时序按原深度缺失规则暂停。
- 横滚超过 `pose3d_upright_roll_deg`（3°）时，本帧二维姿态为未知。
- 重力方向相对上次参考变化超过 `pose3d_camera_motion_deg`（2°）时，清空二维的像素基线和疑似计时（已确认的跌倒保留）。因此云台转动期间二维跌倒只会漏报、不会被画面整体位移误触发；三维规则在重力坐标下计算，不受转动影响。
- 二维确认跌倒仍然需要 `pose_upright_confirmed=true`；三维仍然需要 `pose3d_gravity_confirmed` / `pose3d_ground_confirmed`。动态来源只是逐帧提供数值，确认开关的含义变为“已人工核实所选来源可信”。

**验证**：171 项单元测试（新增地面拟合 9 项、动态重力 7 项、实测地面统一定位 3 项）；合成场景下，相机抬头 15°、横滚 2°、墙在 2.5 m、4 mm 噪声、10% 空洞，10 个随机种子的法向误差均 ≤0.3°、高度误差 ≤1 cm；墙在 1.8 m 的窄地板条判为无效。ROS 运行时测试 `tests/test_floor_runtime.py` 覆盖话题与 header、稳定判定、地面重力下的三维跌倒、无地板时不复用重力，以及统一定位按完全相同的时间戳匹配实测地面。以上均为合成数据，未在真实地板、反光瓷砖或云台上验证。

## 标定与配置

不需要新增控制开关，C 显式入口继续 `scripts/start_c.sh` / `route:=yolo_pose`。新定位节点会随 C 启动，默认因安装/地面未确认保持 NOT_READY。

1. 在安装配置的 `/perception/unified_localizer` 下确认 `extrinsics_calibrated` 和 `ground_plane_confirmed`，提供正确 `ground_z_m`，并确保传感器采集时刻可查到 base←optical TF。仅改 frame 名称不构成标定。原 ground_localizer 和 target_transform 各自的确认项仍独立。
2. 在 pose.yaml 配置 `pose3d_up_x/y/z` 为**校正后光学坐标系中的单位向上向量**。设 base←optical 旋转为 R，平地 base 的上向量为 (0,0,1)，则光学 up = Rᵀ(0,0,1)。`pose3d_camera_height_m` 为光学中心高于地面高度；不是机身外壳离地高度。
3. 实测后才将 `pose3d_gravity_confirmed`、`pose3d_ground_confirmed` 设 true。默认 up=(0,-1,0)、高度 1 m 只是占位。可用 `pose3d_enabled=false` 做原二维对照。

以上假设相机重力方向和地面稳定；车体俯仰、斜坡或移动造成的姿态变化需要重新验证，尚未接 IMU 动态补偿。新增 `pose3d_depth_gap_s=0.35` 控制三维深度短缺容忍；安装配置中 `body_contact_confirm_frames=3`、`body_contact_max_age_s=0.75`、`body_contact_max_offset_m=0.6`、`body_contact_consistency_m=0.15` 和 `body_contact_drift_std_mps=0.3` 控制躯体映射。主要长度、角度、时序和来源质量门槛可通过对应节点参数调整；其余几何健全性检查见代码。统一定位和三维姿态参数的空间约定必须来自同一安装标定，当前没有把“读取到参数”当作“已验证参数正确”。

Foxglove C 布局增加统一接地点、来源/误差与统一目标面板；原光学目标和骨架保留，两个参考点分别展示。
