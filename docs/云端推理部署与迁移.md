# 云端推理部署与迁移

适用：当前拍照推理入口的舌诊、安全帽、PCB 三个模型。小车负责播报、停车保护、拍照及校验结果；另一台电脑负责 GPU 推理。面诊暂无模型。语音口令“舌苔检测”的旧 `tongue_mode` 是独立入口，不由本文配置替换。

## 1. 换机器时需要改什么

| 地址/端口 | 当前值 | 用途 | 换云端机器时怎么处理 |
|---|---|---|---|
| 推理网关 | WSL `127.0.0.1:8200` | 统一接收三类图片、返回 JSON/标注图 | 在新电脑启动同一网关；可以更改其监听端口 |
| 舌诊内部服务 | WSL `127.0.0.1:8096` | 网关访问冻结舌诊后端 | 保持仅本机监听；若改端口，重新生成网关配置中的 `models.tongue.port` |
| 小车推理地址 | `http://127.0.0.1:18200` | 当前车端 `inference_url`，通过 SSH 转发到网关 | **最省事：保留18200，只把转发连接移到新电脑**，小车业务配置无需改 |
| 原指令/上传服务器 | `http://192.168.31.149:5011` | `cloud_url`，旧 upload 上传或 HTTP bridge 的命令/结果通道 | 与模型推理地址不同；只换模型电脑时通常不改 |
| 另一端调用小车的 ROS 服务 | `/inspect/tongue`、`/inspect/helmet`、`/inspect/pcb` | 当前已启用；同步返回 JSON 和 JPEG | 不是 HTTP 端口；需同版本 Humble 接口、域号182或通过SSH调用 |

**当前小车常驻配置为 `pipeline_mode=infer, with_ros_api=true, with_bridge=false`。** 没有 HTTP 命令轮询；调用 `/inspect/*` 后结果直接交给 ROS 调用方，不会额外 POST 到5011，也不再调用旧 `/images`。`cloud_url` 仍在配置中，不能据此认为 HTTP bridge 已开启。若将来显式启用 bridge，其最终 event 与独立 `/result-image` 合同见[云端协议第9节](云端拍照任务接口协议.md#9-显式-infer-模式分析结果与标注图)。

## 2. 在另一台电脑准备模型与环境

### 2.1 获取完整仓库模型

建议使用 NVIDIA GPU + Linux x86_64，或 Windows 上的 WSL2 Ubuntu。当前验证环境是 RTX 5060 8GB + WSL；其他型号、原生Windows、macOS和Jetson不在本次验证范围。新机器先确认 `nvidia-smi` 能看到GPU；WSL还需Windows主机的NVIDIA驱动正常。

```bash
sudo apt-get update
sudo apt-get install -y git git-lfs python3-venv
# 仓库地址不变；模型入库PR合并前，请检出PR实际分支
 git clone https://github.com/Shimmersss/ROS-CAR.git
cd ROS-CAR
git lfs install --local
git lfs pull --include='models/inference/**'
python3 scripts/prepare_inference_deployment.py --verify-only
```

三个资产总计 **1,727,778,985字节（约1.61GiB）**，不是三个很小的 `.pt`：舌诊ZIP自包含分割器、10个分类器、服务源码、冻结配置和45项文件哈希。权重与ZIP使用 Git LFS，普通Git提交保存指针，实际文件也上传到同一仓库的LFS存储。克隆后若文件只有几百字节，说明尚未拉取LFS；不要把指针当模型加载。

模型清单及SHA256见 [models/inference](../models/inference/README.md)。更新权重会增加LFS对象；不要重新压缩舌诊ZIP或随意更新冻结阈值。LFS下载/存储遵循[GitHub LFS配额](https://docs.github.com/en/billing/concepts/product-billing/git-lfs)，本方案不购买额外额度。

### 2.2 生成本机路径、私有令牌和启动脚本

以下 `RUNTIME` 只是本机运行目录，不是服务器地址。程序默认放入忽略的 `artifacts/`，不把环境、解压副本、令牌或图像提交Git。

```bash
export RUNTIME="$PWD/artifacts/inference-runtime"
python3 scripts/prepare_inference_deployment.py --runtime "$RUNTIME"
```

脚本只做准备工作，不启动模型或修改小车：校验三个资产，原样解压舌诊包，逐项校验45个冻结文件；生成 `gateway.private.yaml`、0600的 `gateway.token`、`run-tongue.sh`、`run-gateway.sh`。再次执行保留已有token。需要更改端口时：

```bash
python3 scripts/prepare_inference_deployment.py --runtime "$RUNTIME" \
  --port 8200 --tongue-port 8096
```

准备脚本生成的是本机绝对路径，复制整个运行目录到另一台电脑后应在新电脑重新运行准备脚本，不能继续使用旧机器的 `/root/...` 路径。

### 2.3 安装两个独立Python环境

当前GPU组合为 torch2.8.0 + torchvision0.23.0 + CUDA12.8轮子，安装命令来自 [PyTorch官方版本表](https://pytorch.org/get-started/previous-versions/)。舌诊原包 `requirements_model.txt` 仍保留历史CPU参考版本，**本次GPU部署不要直接安装它覆盖2.8环境**。不修改该原文件。

```bash
python3 -m venv "$RUNTIME/venv-yolo"
"$RUNTIME/venv-yolo/bin/python" -m pip install \
  torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
"$RUNTIME/venv-yolo/bin/python" -m pip install -r services/inference_gateway/requirements.txt

python3 -m venv "$RUNTIME/venv-tongue"
"$RUNTIME/venv-tongue/bin/python" -m pip install \
  torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
"$RUNTIME/venv-tongue/bin/python" -m pip install \
  -r "$RUNTIME/tongue_cloud_server_20261015/requirements_core.txt"

# 两个环境分别做一次真实CUDA运算，不只检查is_available
for env in venv-yolo venv-tongue; do
  "$RUNTIME/$env/bin/python" -c \
    "import torch; x=torch.randn(64,64,device='cuda'); print(torch.__version__,torch.cuda.get_device_name(),(x@x).sum().item())"
done
```

当前三GPU后端全部驻留并完成推理后曾测得整卡4519/8151MiB，含Windows桌面占用，只是当时快照，不是任意输入的峰值保证。舌诊原CPU/GPU数值比较最大差0.008267，未达0.001；用户已明确允许当前GPU继续使用，失败记录保留，不代表数值对齐或准确率通过。新硬件仍须自检，不能靠改阈值通过。

### 2.4 按顺序启动

开两个终端，均先设置同一个 `RUNTIME` 的绝对路径：

```bash
# 终端1：先启动舌诊；首次加载模型需等待
bash "$RUNTIME/run-tongue.sh"
# 终端2：舌诊ready后启动三模型网关
bash "$RUNTIME/run-gateway.sh"
```

网关初始化时检查舌诊；若舌诊尚未ready，该后端会不可用，待舌诊ready后重启网关。检查命令不输出token：

```bash
export RUNTIME=/absolute/path/ROS-CAR/artifacts/inference-runtime
"$RUNTIME/venv-yolo/bin/python" - <<'PY'
import json, os, urllib.request
from pathlib import Path
root=Path(os.environ['RUNTIME'])
cfg=json.loads((root/'gateway.private.yaml').read_text())
request=urllib.request.Request(f"http://127.0.0.1:{cfg['port']}/health/ready",
    headers={'Authorization':'Bearer '+(root/'gateway.token').read_text().strip()})
with urllib.request.urlopen(request, timeout=15) as response:
    data=json.load(response)
print({key:(value['ready'],value['device']) for key,value in data['models'].items()})
assert all(data['models'][kind]['ready'] for kind in ('tongue','helmet','pcb'))
PY
```

期望 tongue为cuda、helmet/pcb为cuda:0且ready=true；face为不可用是当前正常状态。`/health/ready` 的HTTP200和顶层ready不能代替逐个模型核对。以上进程默认前台运行；可以使用独立服务管理器监督，但本次没有为新电脑配置开机自启。WSL/Windows休眠或退出会中断推理，需保持运行。

## 3. 最方便的迁移：保留小车18200转发端口

新电脑只需能SSH到小车；小车不必直接连通新电脑的8200。下面的 `<车端IP>` 当前为192.168.31.145，以现场为准。

1. 按上一节在新电脑让三个模型ready。
2. 安全地把新电脑的 `gateway.token` 传到小车私有目录。该文件内容不要粘到聊天、命令行参数或日志：

   ```bash
   scp "$RUNTIME/gateway.token" wheeltec@<车端IP>:.config/roscar/gateway.token.next
   ssh wheeltec@<车端IP> 'chmod 600 ~/.config/roscar/gateway.token.next'
   ```

3. 先在旧5060 WSL停止 `/root/roscar-models/onboard-link/run.sh` 及它的SSH子进程。否则旧脚本每10秒重连，可能抢占18200。只停止这一专用连接，不停止其他SSH或整车服务。
4. 新电脑使用已获授权的SSH账号/密钥建立转发；首次须核对小车主机指纹。示例：

   ```bash
   # 8200随新网关的实际端口修改；18200保持不变
   ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 \
     -o ServerAliveCountMax=3 -R 127.0.0.1:18200:127.0.0.1:8200 \
     wheeltec@<车端IP>
   ```

   当前旧WSL专用密钥只允许小车loopback18200转发且禁用shell，不能用它执行上面的scp或远程管理。新机器应由管理员单独分配访问权限，不把旧私钥复制进仓库。若仍使用受限密钥并更改18200，还须同步 `authorized_keys` 的 `permitlisten` 限制。

5. 小车空闲、无检测任务时，在小车终端切换token并只重启拍照服务：

   ```bash
   mv ~/.config/roscar/gateway.token ~/.config/roscar/gateway.token.previous
   mv ~/.config/roscar/gateway.token.next ~/.config/roscar/gateway.token
   systemctl --user restart roscar-capture-inference.service
   ```

   网关token在执行器启动时读取，覆盖文件后也要重启适配服务。不要重启整车主服务，不改变运动授权或自动跟随设置。

6. 在小车按第5节调用 `/inspect/*`；确认JSON的model.device/版本、JPEG/SHA和播报。新连接终端退出即断开；要长期运行可用监督服务重连，当前旧WSL的脚本是这类受限连接示例。

迁移失败时，先恢复旧连接与 `gateway.token.previous`，再重启拍照适配；服务应明确失败，不以CPU或假图冒充成功。

## 4. 需要修改小车地址或上传端口时

### 4.1 推理地址：inference_url

当前用户unit：`~/.config/systemd/user/roscar-capture-inference.service`。参数是只读启动配置，不能用 `ros2 param set` 热修改。若保留18200，只改转发右侧的8200即可；若确实要把小车端口换为18201，转发左侧和下面URL必须一起更改。

推荐用drop-in替换启动命令，**同时保留当前overlay、robot安全配置和唯一TTS/guard**：

```bash
systemctl --user edit roscar-capture-inference.service
```

```ini
[Service]
ExecStart=
ExecStart=/bin/bash -lc "source /opt/ros/humble/setup.bash; source /home/wheeltec/ROSCAR-current/install/setup.bash; source /home/wheeltec/ROSCAR-capture-infer-2b27f36/install/setup.bash; exec ros2 launch capture_task capture_task.launch.py safety_profile:=robot pipeline_mode:=infer inference_url:=http://127.0.0.1:18201 inference_token_file:=/home/wheeltec/.config/roscar/gateway.token with_bridge:=false with_ros_api:=true cloud_url:=http://192.168.31.149:5011 token_file:=/home/wheeltec/.config/roscar/c518-capture.token camera_profile:=gemini_rgb_tongue_v1 save_images:=false"
```

```bash
systemctl --user daemon-reload
systemctl --user restart roscar-capture-inference.service
```

如果不用SSH而直接访问新电脑的可信局域网IP，准备时显式 `--host 0.0.0.0`，小车的 `inference_url` 改为 `http://<新机器IP>:8200`；只允许可信内网访问并使用同一token，不能把127.0.0.1误认为远端机器。跨不可信网络继续使用SSH/TLS，不裸露Bearer令牌。

### 4.2 旧上传/命令服务器：cloud_url

`cloud_url` 决定 upload 模式的 `/v1/tasks/{id}/images` 接收端，以及已启用bridge时的commands/ack/events/result-image通道。它与 `inference_url` 分开，两个token也分开。

- 当前infer+ROS入口：改 `cloud_url` **不会**改变模型上传去向，也不会自动开启HTTP轮询。
- 未来明确启用HTTP bridge：配置支持新协议的服务器 `cloud_url` 与 `token_file`，并显式 `with_bridge:=true`；不要指向仅提供 `/v1/infer/*` 的模型网关。
- 明确回退旧upload时：停用新infer服务，再启用 `c518-capture-adapter.service`，需要变更旧上传端口就在该unit的 `cloud_url:=http://<接收端IP>:<端口>` 修改并重启旧适配。不要让两套执行器同时运行。
- `cloud_url` 可带统一路径前缀（如 `/roscar`）；当前推理网关路由不提供此类前缀配置，`inference_url` 使用网关根地址。

通过整机脚本新部署时，等价变量为 `CAPTURE_PIPELINE_MODE`、`CAPTURE_INFERENCE_URL`、`CAPTURE_INFERENCE_TOKEN_FILE`、`CAPTURE_CLOUD_URL`、`CAPTURE_TOKEN_FILE`。当前独立systemd unit在命令行显式传参，仅改私有env不会覆盖这些显式参数。

## 5. 验证与排错

在小车终端加载**增量overlay**；只加载current会得到旧版Action/服务定义：

```bash
source /opt/ros/humble/setup.bash
source ~/ROSCAR-current/install/setup.bash
source ~/ROSCAR-capture-infer-2b27f36/install/setup.bash
export ROS_DOMAIN_ID=182 ROS_LOCALHOST_ONLY=0
export FASTRTPS_DEFAULT_PROFILES_FILE=~/ROSCAR-current/ros2_ws/src/perception_bringup/config/fastdds_robot.xml
systemctl --user is-active roscar-robot.service roscar-capture-inference.service
python3 ~/ROSCAR-capture-infer-2b27f36/scripts/inspect_client.py pcb \
  --timeout 180 --output ~/ROSCAR-capture-infer-2b27f36/artifacts/inspection
```

舌诊/安全帽分别把pcb改为tongue/helmet。正常完整任务可能约17–25秒，包含播报、准备、采集及网络；不等于GPU推理本身耗时。没有舌体应retake、无图；analyzed时必须同时核对JSON与JPEG哈希。当前真实返回的字段和样例见[返回值说明](拍照推理接口返回值.md)。

| 现象 | 优先检查 |
|---|---|
| 连接拒绝/超时 | WSL是否运行、8200是否监听、18200隧道是否仍在；SSH退出是否报转发端口被占用 |
| 401/403 | 两端gateway.token是否一致，是否重启车端执行器读取新token；不要把cloud token混用 |
| model_unavailable | 网关各模型ready、LFS文件大小/SHA、GPU环境；舌诊启动晚于网关时重启网关 |
| 找不到/inspect或服务类型不符 | 是否加载增量overlay、重新构建同版本interfaces；不要重复启动执行器来修发现问题 |
| CLI仍显示旧/capture服务 | 可能是DDS/CLI发现缓存；等待刷新，用新节点按服务所有者核查，不能据缓存叠加新节点 |
| 舌诊返回retake | 查看quality.failures/retake_hints，labels为空表示没分类，不是八项阴性 |
| 没有出声 | 检查唯一SpeakText队列、USB PCM播放开关、PulseAudio mute；不要新建第二个TTS所有者 |

本次只提供部署/迁移工具，不自动切换当前在线小车或WSL服务；运动保护、默认upload兼容和冻结模型契约均不改变。
