# C 方案本机验证（2026-10-07）

本次在 Mac 与既有 Linux ARM64 Humble 容器验证，不继续车上部署，不修改算法参数。

## 相机与真实模型

- Orbbec SDK 1.10.16 识别到 SV1301S_U3，序列号 AY2755200PW，固件 RD3013。深度 640×400，300 帧，约 29.97 FPS；保存的10帧有效深度比例84.48%–85.81%。
- 设备内参、畸变、RGB-D 外参与仓库保存值逐项一致。软件深度投影可运行，投影后有效像素约63%–64%；这不等于物理配准精度通过。
- UVC 彩色640×480读取成功。当前镜头朝天花板，没有人体，Pose输出0人。彩色与深度分开采集，未核验同步误差或已知距离。
- 官方Pose权重在示例图片检测到4人，17点输出与重复静态帧ID检查通过，Mac CPU单次约122–132毫秒。真实相机静态图约143–216毫秒。以上不是视频稳定帧率或Jetson性能。
- OSNet实际ONNX在两个独立人体裁剪提取特征并完成脚本化身份恢复。整图存在重叠/关键点不足拒绝，未放宽质量门槛；不算真人遮挡恢复验收。

## ROS 检查与异常

14包原生ARM64容器构建、138项感知逻辑测试通过。C融合开/关、配准契约、B测距/TF/并发、地面/先验、ReID观察层和统一定位测试通过。

首轮在身份恢复测试失败：期望`0:8`，实际流epoch已变为1并恢复到`1:8`。第二轮身份测试通过，但三维跌倒测试发生epoch重置，清空过程后只输出静态躺卧。随后独立补测三维姿态通过。没有修改产品阈值或测试来掩盖失败；重置究竟来自采集间隔、调度还是时钟仍需进一步定位，不能把多轮分别通过写成整套稳定通过。

虚拟机最初显示运行但VZ日志明确报“virtual machine is no longer live”，已停止失效实例并启动原Colima，复用原镜像。未安装大型环境或删除业务数据卷。
