# 云端拍照任务 HTTP v0 协议

本轮提供四类独立拍照任务 `face / tongue / helmet / pcb`；只采集并上传，不运行推理，不走语音意图链。参考服务：`scripts/mock_capture_cloud.py`。全部 JSON 为 UTF-8 对象，禁止重复键、NaN，最大 2 MiB。ID 匹配 `[A-Za-z0-9_-]{1,64}`。

地址由 `CAPTURE_CLOUD_URL` 指定（http/https 地址，可带路径前缀，不含账号、查询或fragment），默认 mock `http://127.0.0.1:8090`；机器人默认 `roscar-01`。正式地址、TLS、token 下发由云端团队确认。Python 客户端直连，不读取系统代理。例如 https://host/roscar/ 会规范为 https://host/roscar，以下所有 /v1 路径附加在 /roscar 后；各段仅接受 [A-Za-z0-9._~-]+，拒绝空段、点/双点段和百分号编码。

鉴权头 `Authorization: Bearer <token>`，来自环境变量 `CAPTURE_CLOUD_TOKEN` 或仅当前用户拥有、0600 的私有文件。不写项目文件、日志或 URL。mock 默认只监听本机；若设 token，admin 接口也需相同 token。

| 方法 / 路径 | 输入与返回 |
|---|---|
| GET `/v1/robots/{robot_id}/commands/next?wait=1` | 200 返回一条指令；204 无指令；服务端须支持 wait=0..20 的整数秒；默认1秒 |
| POST `/v1/robots/{robot_id}/commands/{command_id}/ack` | `{"accepted":true,"reason":"accepted"}` 或 false + busy / invalid / expired / voice_mode_active / rejected / not_active / unsupported / unavailable 等 |
| POST `/v1/robots/{robot_id}/tasks/{task_id}/events` | `{"phase":"CAPTURE","detail":"","seq":1}`；结束含 result 对象；seq 每个 task_id 单调递增，重传同一事件应幂等 |
| POST `/v1/tasks/{task_id}/images` | JPEG 原始字节，Content-Type image/jpeg，最大 12 MiB |
| POST `/v1/robots/{robot_id}/heartbeat` | 每 10 秒 `{"state":"idle","task_id":"","camera_ok":true,"tts_ok":true,"version":"0.1.0"}` |

小车默认 poll_wait_sec=1（CAPTURE_POLL_WAIT_SEC / launch同名参数），空闲约1请求/秒；有待发事件时 wait=0。合法配置为0–20整数，非法启动报错；GET的总时限和socket超时预算均为实际wait+2秒。心跳目标间隔10秒。单HTTP线程调大wait会使待发送事件、取消处理、心跳额外推迟最多wait秒；服务端有新指令应立即返回，不能等满wait。

执行器状态超过1.5秒未收到，新的拍照指令ack unavailable；心跳state=unknown、camera_ok=false、tts_ok=false，bridge_state.executor_stale=true。执行模式active状态超过6.5秒未刷新视为不活跃，解析失败按active处理并使用同样期限。全部基于本机monotonic接收时间。

拍照指令：

```json
{"command_id":"c-001","type":"capture","task_id":"t-001","task_type":"pcb","params":{"prepare_sec":3},"ttl_sec":60}
```

取消：`{"command_id":"c-002","type":"cancel","task_id":"t-001"}`。只取消匹配的当前任务。`speak` 在 v0 本实现中保留协议校验，返回 `unsupported`；后续接入前须验证禁用词及唯一 TTS 所有权。

仅可覆盖 announce / prepare_sec。播报非空且最多 300 字符；Unicode 规范化、忽略标点空白后禁用 RESERVED_STOP（完整列表见 catalog.py），以免扬声器触发常开紧急监听。违规直接拒绝。准备时间 0–30 秒，ttl 0–600 秒；0 用默认 60 秒。时限从桥接收到指令开始计算，发给执行器时扣掉已耗时间。忙时不排队。

上传头必须包含 `X-Robot-Id / X-Task-Type / X-Capture-Id / X-Frame-Index / X-Capture-Time / X-Camera-Profile / X-Image-Sha256 / X-Quality`。时间为 UTC ISO8601；X-Quality 为 JSON，含 brightness / sharpness / rb_ratio / width / height（数字）。质量不达标默认 warn，如实上传指标，不放大图片。

200 回执：

```json
{"status":"received","task_id":"t-001","capture_id":"cap-001","upload_id":"u-001"}
```

task_id、capture_id 必须原样回显，upload_id 也须符合 ID 规则。同 capture_id 重传以 SHA256 幂等：409 仅在回执额外 `sha256` 与本次完全相同且其余字段合法时视为成功；否则失败。4xx 不重试，5xx/网络错误最多三次尝试（间隔 1、2 秒），受总时限约束。取消关闭当前上传连接；服务端可能已收到图片，取消不能撤回云端已接收的数据。

指令 ID 保留完整 10 分钟去重，到期清理；重复返回原 ack，不重做。云端应始终使用新的 task_id 标识一次业务任务。执行器拒绝 ROS goal 时 action 协议没有 result；拒绝原因在 `/capture_task/result` 发布，bridge 在 ack 带原因。

轮询断网退避 1、2、4…30 秒；401/403 进入 auth_failed、60 秒后重试，bridge自身不语音播报网络故障；已接受的拍照任务上传失败则由执行器播报一次目录中的安全失败提示。执行器上传 401/403 会在任务结果中标注，bridge 同样进入 auth_failed。未送达的 ack/events 在有界内存队列重试；进程重启不保证重放，云端需要根据任务 ID 和回执对账。

## 本机示例

```bash
python3 scripts/mock_capture_cloud.py serve --store artifacts/capture-mock
python3 scripts/mock_capture_cloud.py send pcb
python3 scripts/mock_capture_cloud.py status
python3 scripts/mock_capture_cloud.py cancel t-001
curl --noproxy '*' -X POST http://127.0.0.1:8090/admin/commands \
  -H 'Content-Type: application/json' \
  -d '{"command_id":"c-manual","type":"capture","task_id":"t-manual","task_type":"face","params":{},"ttl_sec":60}'
```

路径前缀示例：

```bash
python3 scripts/mock_capture_cloud.py serve --prefix /roscar
# 执行器和bridge均设置 CAPTURE_CLOUD_URL=http://127.0.0.1:8090/roscar
python3 scripts/mock_capture_cloud.py --url http://127.0.0.1:8090/roscar send helmet
python3 scripts/mock_capture_cloud.py --url http://127.0.0.1:8090/roscar status
```

生产CloudClient.request内部只接受/v1/路径；mock CLI使用独立admin_request，仍附加同一个前缀。

故障参数：`serve --fail-upload 500|409|401`、`--slow-upload 10`、`--drop-poll`。409 注入会先保存本次相同 SHA 图像再返回幂等回执。mock 的 admin 命令队列是单机器人测试队列，不能用作多机器人生产调度。


## ROS发起任务的增量约定（2026-10-13，待云端确认）

既有HTTP v0路径、JSON字段、去重、TTL、取消及bridge不变。执行器额外发送可选请求头 `X-Task-Source: cloud | ros_api | local_test`，值来自原action的source；兼容旧客户端未携带该头。

可选ROS门面自动生成 `ros-<32位hex>` task_id；显式提供的合法ID原样保留，建议ros-前缀避免与云端冲突。云端应接受**未经自己下发**的ROS任务图片上传，仍走 `/v1/tasks/{task_id}/images` 和原回执契约，并按X-Task-Source区分来源。只返回上传回执，推理/诊断结果不从这个ROS接口返回。

ROS任务不经过bridge，没有对应的command/ack/events；执行器状态仍使既有心跳反映busy。云端cancel只取消bridge自身当前任务，不能取消ROS门面任务；ROS取消也不能取消bridge任务。

**待云端确认**：正式服务如果拒绝未下发ID，ROS门面将返回failed/upload_http_404。本机mock默认接受有效上传；可用 `serve --reject-unknown-task` 模拟严格服务，仅接受通过commands/next下发过的task_id，未知返回404。该开关默认关闭，不改变旧mock行为。
