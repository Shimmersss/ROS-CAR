# Gemini 录像回放分析

数据为 `data/recordings/gemini-20261007-session1`。本次按每6帧取1帧（约5Hz）运行实际YOLO26s-Pose、ByteTrack、二维状态及C深度融合，共610帧。使用采集时间推进状态机，不使用离线推理耗时。此采样率不同于完整30Hz跟踪，ID表现不能直接等同实时表现。

彩色先去畸变；原生深度使用设备内外参投影到彩色平面。按主机接收时间最近邻、最大40ms配对，542帧有候选配对；这是诊断配对，不证明曝光同步或物理配准精度。未确认安装高度/重力，未启用三维状态、地面坐标或确定跌倒。ReID未运行。

## 观察到的问题

以下按画面中最大人体框汇总，路人经过时最大框可能换人，不代表已锁定目标。动作依据抽样画面目视核对，没有完整逐帧人工标签，不计算整体准确率。

| 片段 | 输出与观察 |
| --- | --- |
| 29–37秒，下蹲 | 40/40个样本为坐蹲，有身体深度 |
| 40–50秒，站立 | 48站立、2坐蹲；存在短暂跳变 |
| 60–70秒，转身 | 主体轨迹从0:1变为0:4，中间有无ID/无人体样本；不能据此称ReID失效，因为未启用 |
| 88–94秒，坐地转躺卧 | 30个样本中12个判站立、13未知、4躺卧、1坐蹲；二维透视歧义明显 |
| 94–98秒，横卧 | 19/20躺卧，1未知 |
| 100–110秒，坐起/起身 | 36未知、6坐蹲、8站立；需要进一步逐帧标注动作过渡 |

相机明显倾斜，不能把画面竖直直接当重力。第一段缺深度主要包含深度尚未开始采集的时间，不可解释为算法距离限制。采集时间检查：彩色最大间隔95.97ms，深度82.96ms；wall与monotonic间隔差最大约0.084ms。这段采集没有复现先前ROS测试的长间断，但未定位那次epoch重置根因。

## 可以怎样优化

1. **站立/坐蹲切换增加短时确认。** 在12–27、40–50、70–83秒的有ID最大框样本上试算0.3秒切换确认：189个样本中原来7个坐蹲，处理后全部站立。仅为本录像上的显示层候选实验，会增加切换延迟，未接入生产规则；不能修正坐地时的持续误判，也不能用于保持缺失关节的状态。
2. **优先补安装标定，再用真实三维约束状态。** 三维躯干方向、距地高度和腿部角度可帮助区分“投影看着直立”和真实站立。不能从这段倾斜录像随意猜相机高度，或用统一脚下坐标补造关节。
3. **用60–70秒做身份恢复专项。** 后续启用真实OSNet观察层重放，核对相似外观、侧身质量拒绝和恢复延迟；不要直接把所有新ID接回旧ID。

未调整正式阈值，没有将同一段视频试算写成独立验证集提升。建议先做状态切换候选的独立录像验证，再决定默认开启；当前首要错误仍是坐地/躺卧的二维歧义。
