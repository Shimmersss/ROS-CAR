# 2026-09-20 新增代码审查与修复

范围：本次未提交的 N10P 接入、motion_guard、navigation_bringup、跟随启动整合、同步/构建/录包脚本及 Foxglove 配置。保留此前用户已有更改；本轮无 SSH、部署或硬件操作。

| 问题 | 原有影响 | 修复与验证 |
|---|---|---|
| 停车保护未验证雷达近距离盲区 | 最小量程过大或安装偏置时，扫描表面正常仍可能接受车体外不可见区域 | 要求 range_min 盲区完全位于已确认矩形车体内；新增量程和偏置边界测试 |
| SIGTERM 未执行停止清理，重复信号可打断清理 | 常用脚本停止时无法保证走完最终零速度发布和节点销毁 | 跟随、保护及导航入口统一处理 SIGINT/SIGTERM，进入清理后屏蔽重复停止信号；实际独立进程验证退出码和最终零速度，组合 launch 检查无异常堆栈 |
| 直接跟随请求 frame 写死 base_link | safety_config 选 base_footprint 后，保护一直拒绝请求 | 增加只读 base_frame，并从安全配置传给跟随器；ROS 启动测试验证发布 frame |
| 红色组合入口只覆盖 source，未覆盖目标 frame | 使用默认安全配置时仍要求 Astra 光学 frame，红色目标无法通过 | 显式 target_frame 参数，红色默认 camera_color_optical_frame；支持 TARGET_FRAME 环境变量 |
| 组合重构漏传 performance_enabled | 关闭性能统计后跟随器仍发布指标 | 启动链恢复参数透传，测试确认禁用时无指标发布者 |
| 观测 TF 短暂落后就锁存故障 | 相机数据先于该时刻里程计 TF 到达时，正常跟随容易中断 | 最多等待 0.15s，期间输出零；不使用最新 TF 替代观测时刻 TF；短延迟恢复、持续缺失锁存的 ROS 测试 |
| 导航 JSON 状态字段校验不完整 | Infinity 时间戳可抛未捕获异常；错误类型可能被隐式转换 | 严格检查时间戳整数及 allow_motion/fault 布尔类型；畸形消息拒绝且节点不崩溃 |
| 雷达健康定时器受 /clock 暂停影响 | 模拟时钟停止时无法持续发布健康状态 | 改为 steady clock；暂停 ROS 时钟的实际 ROS 收发测试；缓存配置参数设为只读，防止表面修改但未生效 |
| 构建/同步入口不完整 | 导航专项依赖手工先构建基础镜像；同步漏导航 Dockerfile；雷达暂存清理范围过大 | 补基础镜像构建和同步白名单，仅清理复制的雷达子树内 COLCON_IGNORE；脚本审查与同步单测 |
