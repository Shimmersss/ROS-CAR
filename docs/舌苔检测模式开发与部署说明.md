# 舌苔检测执行模式：开发与部署说明

日期：2026-10-04。模块来源为独立 clone 的 `codex/tongue-execution-mode` / `1b422eb`，现已移植到以 `0c39068` 为基线的 `codex/voice-tongue-integration`。当前整合入口和本分支验证见[语音舌苔流程整合与验收](语音舌苔流程整合与验收.md)，来源分支的历史验证仍单独保留。

## 1. 实际功能边界

舌苔检测是小车的一个持续执行模式，`mode_id=tongue`。说“舌苔检测”后进入该模式，自动完成一轮：停车保持 → 云端版本检查 → 提示播报并等待完成 → 准备 → 获取新鲜 RGB 原图 → 上传 → 云端分割和判断 → 结果校验 → 本地播报。

检测完成后保持在 tongue 模式，等待“重新拍摄”“播报上次结果”“退出舌苔检测”。退出、取消、调度器失联和模式异常都清理资源并保持 IDLE；不恢复自动跟随。

本次是软件开发。实际摄像头、麦克风、扬声器、服务器互通和车辆停稳仍需 Jetson/人工验收。测试日志会区分真实 ROS 节点与模拟设备/模型，不能用 mock 通过宣称实拍识别正确。

## 2. 模块职责

| 包 | 职责 |
|---|---|
| `execution_mode_interfaces` | 通用 RunMode、ModeCommand、SpeakText、TaskHold 接口 |
| `execution_mode_manager` | 配置化语音词表、单一模式所有者、串行切换与心跳 |
| `tongue_mode` | 舌苔拍摄/云端判断/结果播报，具体阶段与缓存 |
| `voice_command_router` | 唯一 ASR 意图入口，转交模式命令，保留原控制规则 |
| `motion_guard` | 新增停车租约，持有时拦截 ARM 与非 IDLE 模式切换 |
| `xfyun_speech` / `offline_voice` | 原播放队列增加带 ID 的完成/失败/取消确认；仍复用原 TTS 和 ALSA |

默认旧语音 launch 的词表为空、结构化播报 action 关闭，保持旧入口行为。启用模式时显式提供词表和 `enable_speech_action=true`。所有模式由一个 manager 管理，不为每个模式启动一套 ASR/TTS/相机。

## 3. 语音用法

先使用小车现有唤醒方式进入持续语音会话，然后说：

| 命令 | 行为 |
|---|---|
| 舌苔检测 / 进入舌苔检测模式 / 检查舌苔 | 进入 tongue，自动检测一次 |
| 重新拍摄 / 重新检测舌苔 | 新帧、新 request/capture ID；进行中的检测先取消 |
| 播报上次结果 | 只重播本会话最近一次有效分类，不重新上传 |
| 退出舌苔检测 / 取消舌苔检测 / 退出当前模式 | 结束整个模式 |
| 停车 / 停止 / 急停 / 退出语音 | 原停止和锁存逻辑继续有效，同时退出执行模式 |

“不要检查舌苔”按退出处理，不触发拍摄。句中提到舌苔的普通讨论不会触发。重复进入同一模式不重复创建检测。“前进”等运动命令在模式内被拒绝；先退出执行模式再明确发出新运动指令。

当前共享录音和独立 KWS 在 TTS 期间继续运行，普通 ASR 会丢弃播报期间的结果。急停词检出会锁存并取消任务，实际四词召回尚未验收。重复唤醒刷新普通会话，不退出舌苔模式或取消任务提示；普通会话约 8 秒到期后任务继续，结果进入 READY 时开放一个新的 8 秒续聊窗口。联网等待需要取消时，会话已过期则先重新唤醒；明确退出语音会清理执行模式。

## 4. 构建

在具备 ROS 2 Humble 的 Ubuntu 22.04 或 Jetson 专用副本中：

```bash
cd /home/wheeltec/ROSCAR-voice-tongue
source /opt/ros/humble/setup.bash
colcon --log-base log build --base-paths ros2_ws/src --packages-up-to tongue_mode \
  --build-base build --install-base install --symlink-install
source install/setup.bash
```

在本机项目目录中使用相同命令时替换路径。不传 WSL 的构建产物到 aarch64 Jetson，目标设备原生构建。新增包不需要 PyTorch/CUDA 舌象模型，继续由 3090 推理。

统一采用根目录 install，与当前启动脚本路径相符。兼容运行脚本也接受已有 `ros2_ws/install`，但不要在同一运行环境混用两套新旧接口。

## 5. 两种启动方式

### 5.1 仅接入已经运行的小车栈

确认已有相机、唯一 guard、唯一语音路由器和唯一 TTS 都来自含本次通用扩展的新构建。为已有离线语音入口增加：

```bash
bash scripts/run_voice_assistant.sh \
  execution_modes_config:=/home/wheeltec/ROSCAR-voice-tongue/install/execution_mode_manager/share/execution_mode_manager/config/modes.yaml \
  enable_speech_action:=true
```

这是受控替换现有语音模块的启动示例，不应在旧 ASR/TTS/router 仍运行时直接再启动一次。要先辨认实际 supervisor/tmux/systemd，并只切换对应模块。

随后启动模式模块：

```bash
bash scripts/run_tongue_mode.sh
```

该入口默认只启动 manager 与 tongue_mode，不启相机、底盘、运动、ASR/TTS/router。默认 `safety_profile=robot`，需要实时 odom、guard 状态和停车租约。

### 5.2 运动关闭的 Jetson 台架

已有 Astra RGB 驱动单独运行、没有其他语音/guard 的情况下：

```bash
bash scripts/run_tongue_mode.sh safety_profile:=bench with_guard:=true with_voice:=true
```

此入口创建一个 motion_enabled=false、IDLE 的 guard，并启动原离线语音栈与模式组件。bench 允许没有底盘/odom，但必须看到运动关闭的 guard 状态；只能算台架，不能算车辆停稳验收。不能与已有 guard 或语音栈重叠启动。

模式 launch 不会启动相机，复用已有 `/camera/color/image_raw`。语音模型沿用 `/home/wheeltec/ROSCAR-offline`，运行脚本会读取存在的 sherpa-onnx 隔离路径；实际音频设备仍使用原离线语音配置。

## 6. 没有语音时的接口调试

```bash
source install/setup.bash
export ROS_DOMAIN_ID=182   # 与当前目标栈实际域保持一致
python3 scripts/mode_command.py ENTER
python3 scripts/mode_command.py RETAKE

```

CLI 生成新鲜时间戳和唯一 request_id。ModeCommand 过期/重复会被丢弃，不建议手工复制旧消息重复发送。

## 7. 配置与服务器

配置：`ros2_ws/src/tongue_mode/config/tongue.yaml`；词表：`ros2_ws/src/execution_mode_manager/config/modes.yaml`。启动时可以指定 `config:=...`、`catalog:=...` 和 `server_url:=...`。

默认冻结 `cloud_r50_384_cvAC10_passthrough_debug`，digest 为 `c5b9b1e31f73515b44044569b66e64d49861880441273a1fb86cd84774d6a494`。先检查 ready 和 model-info 的版本、CUDA 与标签契约，再拍照。模型版本更换时同步更新两个 expected 字段，不能只改地址。

历史地址为 `http://172.19.128.171:8096`。在 Jetson 上实际验证路由与健康端点，不假定 192.168.* 到 172.19.* 可达。若服务经认证代理提供，客户端可从 `TONGUE_API_TOKEN` 环境变量发送 Bearer，原 HTTP 服务本身尚不因此获得鉴权能力。

继续沿用调试放行流水线，车端不添加未验证的舌象质量阈值。空分割仍 retake。传原始 RGB JPEG，不传 YOLO 标注图，不在车端分割或把整图先缩为 384。

重要参数：prepare 2 秒、JPEG 95、帧窗口必须晚于提示完成、最大接收年龄 0.5 秒、停车租约 3 秒/约 0.5 秒续租、任务上限 150 秒。150 秒仅为当前云端调试配置留余量，正式网络/服务计时验证后应缩短。

## 8. 结果、日志和异常

模型识别舌色淡、尖边红、红点、瘀斑、裂纹、齿痕、厚苔和黄苔八项特征，是多标签。不是疾病诊断。黄苔阴性不解释为白苔，厚苔阴性不解释为薄苔。

- `ok/uncertain` 必须确实执行分类且八项完整，score/threshold 为合法有限数值，decision 与阈值一致；uncertain 不强转二值。
- `retake` 必须没有分类结果，不填八个阴性。
- capture/request/session 和 pipeline 必须匹配当前请求。取消后的网络响应不会保存或播报。
- 失败的新检测会清空可重播的旧成功缓存，不冒充本次结果。
- 相机断流、旧帧、错误颜色格式、云端版本不符、播报提示失败都不继续拍摄/判断。
- mode 持续 READY 时仍有调度器心跳和停车保持续租。心跳丢失、状态过期、odom 非零、lease 失效都退出模式。
- 新模式切换要等待旧 RunMode 的最终结束，不只等待 cancel 请求回包。

记录默认在 `~/.local/state/roscar/tongue/<capture_id>/result.json`，包含 ID、帧序号、尺寸、云端响应和安全 profile。`save_images=true` 时额外保存 capture.jpg；默认关闭。调试结束后按项目留存策略清理，图片和凭据不要提交到 Git。

模式阶段和失败原因还会追加到同目录的 `events.jsonl`，便于检查取消、超时和资源释放。时间为 monotonic，仅供阶段耗时比较。RGB 必须是明确的彩色 encoding，ROS header 与接收时间都要新鲜；相机和最终 `/cmd_vel` 发布者必须唯一。

HTTP 当前没有真正的推理取消接口。客户端可断开连接并丢弃旧结果，但服务器可能继续完成已经开始的 GPU 工作。本地请求串行且可取消，不做无限自动重试。

## 9. 软件验证与人工验收

运行 `bash scripts/test_tongue_mode.sh`。没有 Humble 时只跑纯逻辑并以退出码 2 明确报告 ROS 尚未验证；有 Humble 时构建、运行真实 ROS/mocked IO 集成，再跑旧语音/guard/API 回归。所有测试使用 localhost 和隔离 domain 184，不连接实车。

实际执行结果见副本 `artifacts/` 与 `docs/舌苔检测模式验证记录.md`。对语音队列、guard、模式切换的结论需以日志为准，不以静态编译代替。

需要后续人工参与：

1. 安排 Jetson 专用目录与受控模块切换，验证网络互通。
2. 调相机高度、近距离合焦、光照和舌头在图中的尺寸。
3. 真实说命令、听提示和结果，检验 ASR 是否正确转写“舌苔检测”。
4. 实际观察停车并测试任务期间不恢复跟随。
5. 实拍、取消、重拍、断网、离开画面等验收；若评准确率需要人工参考标签。

## 10. 多模式合并

通用基线只需要合并一次：execution_mode_interfaces、execution_mode_manager、router 通用接入、TTS 确认和 guard 停车租约。后续模式在各自包中实现 RunMode，并在词表追加条目。详见 `执行模式模块接口与合并约定.md`。

该 clone 的 `source-readonly` 指向原本地仓库，不应向它 push。之后在这个副本增加项目真实远端作为 origin，获取最新 main，合入/变基并重新跑相关测试，创建功能 PR；本轮不 push，不修改原工作目录，也不自动 merge 主分支。
