# WHEELTEC 底盘物理串口协议说明

## 1. 当前状态

分支 `a` 的新 A 已接入可选底盘收发和跟随控制，默认不开串口、不使能运动。基础发送为 11 字节速度帧，接收为 24 字节底盘状态帧；代码入口与测试边界见 [方案 A 红色物体跟随](方案A红色物体跟随.md)。

合并提交 `cb0b87a` 记载历史 Jetson 底盘驱动及低速命令链已运行；本轮没有比对在线部署或进行实车测试。串口包保留 COLCON_IGNORE，通过 `scripts/build_chassis.sh` 在副本中显式构建；厂商默认 `mini_mec` 不是已核验车型。

2026-09-14 已静态核对用户提供的 `R550_C30D(2.0)_Mini小车STM32源码_GMR编码器_2026.08.21.zip`。该包是 STM32F407ZG + FreeRTOS 的 C30D 2.0 下位机工程，包含 GMR/正交编码器读取和 R550/V550 车型参数。它的 ROS 串口使用 115200 波特率，11 字节控制帧、24 字节基础回传帧、`0x7B/0x7D` 帧界和异或 BCC 均与本说明所依据的 ROS 2 驱动一致。因此它是当前 R550、C30D 2.0、GMR 编码器硬件组合的对应固件候选；仍需上电从 OLED/电位器档位确认实际选择的是 `Mec`、`4WD`、`MecV` 或 `4WDV`，并读取实物回传后完成最终确认。

## 2. 串口参数与编码

| 项目 | 厂商代码默认值 |
|---|---|
| 设备 | `/dev/wheeltec_controller` |
| 波特率 | 115200 |
| 读取超时 | 本分支 20 ms（原厂 2000 ms） |
| 多字节整数 | 有符号 16 位，高字节在前 |
| BCC | 从帧首开始、到 BCC 前一字节为止逐字节异或 |

速度、角速度、电压、充电电流和距离通常以实际值乘 1000 的整数传输，接收端再除以 1000。源代码没有显式配置数据位、奇偶校验和停止位，因此使用 `serial` 库默认值；启用前应和下位机手册再次核对。

## 3. ROS 向下位机发送

### 3.1 速度控制帧

触发 ROS 话题：`/cmd_vel`，类型 `geometry_msgs/msg/Twist`。

帧长 11 字节：

| 下标 | 字段 | 编码 |
|---:|---|---|
| 0 | 帧头 | `0x7B` |
| 1 | `AutoRecharge` | 自动回充标志 |
| 2 | `SecurityPLY` | 底盘安全标志 |
| 3–4 | X 线速度 | `int16(linear.x × 1000)`，高字节在前 |
| 5–6 | Y 线速度 | `int16(linear.y × 1000)`，高字节在前 |
| 7–8 | Z 角速度 | `int16(angular.z × 1000)`，高字节在前 |
| 9 | BCC | 字节 0–8 异或 |
| 10 | 帧尾 | `0x7D` |

ROS 输入单位是 m/s 和 rad/s。本分支将基本速度限幅为线速度绝对值≤0.15 m/s、角速度绝对值≤0.5 rad/s；非有限输入置零。命令或基本回传超时 0.5 秒、速度发布者数量不是一个时发零。跟随控制器另行禁止倒车。

示例：`linear.x=0.2 m/s`、`linear.y=0`、`angular.z=-0.3 rad/s`、两个标志均为 0 时，数值区为 X=`00 C8`、Y=`00 00`、Z=`FE D4`。完整帧仍需按字节 0–8计算 BCC。

### 3.2 自动回充设置帧

触发话题：`robot_recharge_flag`，类型 `std_msgs/msg/Int8`。

新协议帧：

| 下标 | 内容 |
|---:|---|
| 0 | `0x7B` |
| 1 | `0x01` |
| 2 | 开启时 `0xA1`，关闭时 `0xA0` |
| 3–8 | `0x00` |
| 9 | 字节 0–8 的 BCC |
| 10 | `0x7D` |

关闭回充时，厂商代码还会发送一帧旧协议：字节 1 为 0、字节 2 为 0，其余速度字段为 0。

### 3.3 底盘安全设置帧

触发话题：`chassis_security`，类型 `std_msgs/msg/Int8`。

新协议使用字节 2：开启 `0xB1`，关闭 `0xB0`；随后还发送旧协议帧，字节 2 直接放 `SecurityPLY`。两帧都沿用 11 字节 `0x7B ... BCC 0x7D` 格式。

**2026-09-20 本地已修复：**安全扩展显式将 `tx[10]` 写为 `0x7D`，串口替身测试验证帧尾和 BCC。所核对的 2026-08-21 STM32 固件仍未检出 `0xB0/0xB1` 解析；修复不代表固件支持或实机验收。

### 3.4 灯带设置帧

触发话题：`set_rgb_color`，类型 `std_msgs/msg/UInt8MultiArray`，必须正好包含 `[enable, R, G, B]` 四项。

| 下标 | 内容 |
|---:|---|
| 0 | `0x7B` |
| 1 | 功能码 `0x04` |
| 2 | 使能，输入等于 1 时为 1，否则为 0 |
| 3 | R |
| 4 | G |
| 5 | B |
| 6–8 | `0x00` |
| 9 | BCC |
| 10 | `0x7D` |

### 3.5 机械臂设置帧

触发话题：`arm_cmd`，类型 `std_msgs/msg/Float32MultiArray`。数据 0–2 是三个关节值，数据 3 是夹爪状态。

代码构造的有效格式为：帧头 `0xAA`，三个 `int16(value × 1000)`，夹爪 1 字节，BCC 1 字节，帧尾 `0xBB`，合计 10 字节。

**2026-09-20 本地已修复：**回调及析构的机械臂帧都明确发送 10 字节；回调先要求恰好四项，三个关节须为可表示为 int16 毫弧度的有限值，夹爪须为 0–255 整数。容器编译与串口替身测试通过；启用前仍需确认固件支持。

所核对的 2026-08-21 R550 STM32 固件中也没有检出 `0xAA/0xBB` 机械臂帧解析路径，因此不能认为该机械臂扩展与此底盘固件匹配。

## 4. 下位机向 ROS 回传

### 4.1 基础状态帧

帧长 24 字节：

| 下标 | 字段 | 解码/单位 |
|---:|---|---|
| 0 | 帧头 | `0x7B` |
| 1 | `Flag_Stop` | 厂商代码只保存，未发布为独立话题 |
| 2–3 | 实际 X 速度 | `int16 / 1000`，m/s |
| 4–5 | 实际 Y 速度 | `int16 / 1000`，m/s；仅全向底盘有效 |
| 6–7 | 实际 Z 角速度 | `int16 / 1000`，rad/s |
| 8–9 | X 加速度原始值 | `int16 / 1671.84`，m/s² |
| 10–11 | Y 加速度原始值 | 同上 |
| 12–13 | Z 加速度原始值 | 同上 |
| 14–15 | X 角速度原始值 | `int16 × 0.00026644`，rad/s |
| 16–17 | Y 角速度原始值 | 同上 |
| 18–19 | Z 角速度原始值 | 同上 |
| 20–21 | 电源电压 | 16 位原始值除以 1000，V；正常电压应为非负值 |
| 22 | BCC | 字节 0–21 异或 |
| 23 | 帧尾 | `0x7D` |

有效帧驱动以下 ROS 输出：

| 话题 | 类型 | 内容 |
|---|---|---|
| `odom` | `nav_msgs/msg/Odometry` | 实际速度及由速度积分得到的位置和航向 |
| `imu/data_raw` | `sensor_msgs/msg/Imu` | 由板载 IMU 原始值换算的加速度、角速度及代码计算的姿态 |
| `PowerVoltage` | `std_msgs/msg/Float32` | 电池电压，约每 11 个基础帧发布一次 |

里程计是上位机按收到的速度积分得到的结果，不是下位机直接回传绝对位置。

### 4.2 超声波帧

帧长 19 字节：

| 下标 | 内容 |
|---:|---|
| 0 | 帧头 `0xFA` |
| 1–2 | A 距离，`int16 / 1000` m |
| 3–4 | B 距离 |
| 5–6 | C 距离 |
| 7–8 | D 距离 |
| 9–10 | E 距离 |
| 11–12 | F 距离 |
| 13–16 | 自检/预留，当前代码未使用 |
| 17 | 字节 0–16 的 BCC |
| 18 | 帧尾 `0xFC` |

解析后分别发布 `ultrasonic_data_A` 至 `ultrasonic_data_F`，类型为 `sensor_msgs/msg/Range`。消息中声明视场角 0.52 rad、最小距离 0.02 m、最大距离 5.3 m。G、H 在当前代码中固定为 0，且没有发布对应 Range 话题。

### 4.3 自动回充状态帧

帧长 8 字节：

| 下标 | 内容 |
|---:|---|
| 0 | 帧头 `0x7C` |
| 1–2 | 充电电流，`int16 / 1000` |
| 3 | 红外充电桩信号状态 |
| 4 | 是否正在充电 |
| 5 | 下位机回充模式状态 |
| 6 | 字节 0–5 的 BCC |
| 7 | 帧尾 `0x7F` |

对应 ROS 输出为 `robot_charging_current`、`robot_red_flag`、`robot_charging_flag` 和 `robot_charging_mode`。

## 5. 与人体跟随的接口边界

当前目标位置在 `/perception/target_state`，包含状态、目标 ID、X/Y/Z、水平距离和偏角。它不是串口帧，也不能直接当速度下发。本分支已接入以下可选跟随链路：

```text
/perception/target_state
  -> 跟随控制器（距离/偏角控制、限速、状态机）
  -> /cmd_vel
  -> wheeltec_robot_node
  -> 11 字节速度帧
  -> STM32
```

本分支未注册机械臂、自动回充、灯光或安全扩展订阅，退出只发送基本零速度帧，因此上述原厂扩展缺陷路径不可由 ROS 命令触发。启用物理运动前仍需核验实际车型和协议、实物回传、急停/断线保护以及离地轮与受控场地测试。
