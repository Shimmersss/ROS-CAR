# Demo 跌倒暂停、静止延续与主人冻结

适用 `demo/showcase-20261016`，2026-10-16。本轮是本机软件与离线验证，未部署 Jetson、未进行现场跌倒或运动验收。

## 入口与默认值

`bash scripts/run_demo.sh` 在原演示入口上启用下列行为；仍默认 `MOTION_ENABLED=false`，固定关闭跟随自动授权和目标故障自动恢复。相机序列号、模型及 Pose Python 仍须显式配置。

| 项目 | 通用默认 | Demo |
|---|---|---|
| `pause_on_fall` / `FOLLOW_PAUSE_ON_FALL` | false | true |
| `fall_resume_s` / `FOLLOW_FALL_RESUME_S` | 3 秒 | 3 秒 |
| `target_grace_s` / `FOLLOW_TARGET_GRACE_S` | 通用跟随入口 0.6 秒 | **0 秒** |
| `height_continue_requires_stationary` | false | true |
| `height_continue_s` | 通用配置 0 秒 | 6 秒 |
| `owner_hold_on_fall` | false | true |

新增 `ros2_ws/src/perception_bringup/config/pose_fixed_27cm_demo.yaml`，仅适合原固定机位 27 cm / 上仰 15.1° / 横滚 0.5°。原 `pose.yaml`、`pose_fixed_27cm.yaml` 未修改。显式设置 `POSE_CONFIG` 会覆盖 demo 默认文件，使用自定义文件时须自行保留以上两个感知开关。原固定机位确认字段仅沿用既有配置，不构成新标定。

将 demo 的目标宽限设为 0，是因为 guard 原有宽限会衰减最后一次有效速度，跟随器发零不能阻止该路径。`follow.launch.py` 拒绝 `pause_on_fall=true` 与正宽限组合；guard 源码、其他故障锁存及通用入口默认值不变。目标失效可能进入 FAULT，恢复服务不复位、不重新授权。

## 行为与边界

**跟随暂停（T2.2）**：消费 `/perception/fall_alarm`。新鲜 SUSPECTED/CONFIRMED 立即发零，并持续压住跟随请求。默认新鲜度 0.5 秒，同时检查消息时间戳和接收时间；失效、重复、倒退、过期及断流均不能解除暂停。启动时也须先收到新鲜告警数据才能发非零请求。连续 3 秒新鲜 NONE 且目标有效才自动解除本地暂停，实际运动始终还需原有新鲜 ARMED_FOLLOW 授权。

可调用 `ros2 service call /demo/resume_follow std_srvs/srv/Trigger '{}'` 请求提前解除暂停；只在最新告警为新鲜 NONE 时接受，执行仍须有效目标。该服务不清 ESTOP/FAULT、不切模式、不授权。SUSPECTED/CONFIRMED 仍活跃时拒绝恢复。告警针对画面内任一人，采用保守的全局暂停。

**静止延续（T2.3）**：`/odom` 时间戳与接收时间均不超过 0.3 秒、时间戳递增、速度有限，且连续至少 0.5 秒满足线速度范数 `<0.02 m/s`、角速度范数 `<0.05 rad/s`，才允许延续。只使用本次静止期间的新鲜真实检测框。开始运动、转动、收到无效/倒退里程计或断流时，立即作废延续框并发布无效空 `person_states_continued`；即使之后重新静止，也须重新检出人体才能建立框。

用于真实检测间跌倒交接的历史框与延续框分开保存，作废延续不破坏原检测交接。延续者仍只进入 `person_states_continued`，不进入 `person_states`，感知节点不发布速度。若人在停车前已经完全出画，无法通过本功能重新找回；不提供后退找人。

**主人冻结（T2.4）**：告警活跃时冻结当前主人丢失计时及其连续性重置计时，不转移身份、不新增有效位置。无效/过期告警不会结束冻结；连续 3 秒新鲜 NONE 后从剩余时间继续，正常找回可恢复 TRACKING。主动释放立即清除冻结，旧冻结不继承给新主人。`OwnerState.lost_for_s` / `reclaim_after_s` 反映扣除冻结后的计时，未新增消息字段。

## 验证方法与结果

运行 `bash scripts/test_demo_container.sh`，复用现有 ARM64 Humble 镜像，独立域 214–217，临时容器退出即删除。使用真实 ROS 跟随器、guard、Tracker/Pose 节点，感知模型、RGB-D、里程计及目标输入为显式合成。验证内容：

- 疑似/确认跌倒后最终 `/cmd_vel` 归零；即使 guard 的目标自动恢复开启，目标找回也不能绕过暂停。
- 无效/过期/断流告警不恢复，连续 NONE 恢复、手动恢复、有效目标条件、ESTOP 不被解除，最终速度出口仍唯一。
- 主人实际丢失超过 5 秒仍保留，告警解除后按剩余时间到期；主动释放清除冻结；原有 2/5 秒重置、ReID 找回与再认领流程回归。
- 静止不足 0.5 秒不延续；静止且有检测后，丢人延续可由真实深度合成平面确认；平移、转动、旧时间戳、断流立即撤销，重新静止不复活旧框。
- 原默认关闭行为、Pose/延续 ROS 回归及相关包纯 Python 单测；shell 语法、launch 参数求值和 demo 包装器验证。

日志在忽略的 `artifacts/demo-fall-validation/` 及 `artifacts/demo-validation/acceptance.log`。测试使用单调仿真 ROS 时钟，产品的时间戳拒绝逻辑未放宽，另有明确旧时间戳和时钟倒退单测。
