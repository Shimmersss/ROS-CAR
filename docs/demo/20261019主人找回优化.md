# 2026-10-19 主人找回确认与多视角优化

源录像：车端 `data/demo-trials/20261019-173404-reid-fixed-follow`。本段成功认领 `0:1`，ReID 主人身份已绑定，跟随授权成功，45 秒后由测试脚本 STOP；原始彩色、深度及状态已保存。与上一段“从未绑定成功”的问题分开分析。

## 原因和采用改动

在短时无效 Pose 后，ReID 关联按原保护清空，但主人身份库及连续跟踪还在。之后仍由检测/VitTrack 跟随的同一主人轨迹，必须重新通过 `match_distance=0.25`；录像中部分有效新视角在约 0.25–0.30，原本符合已绑定核验阈值 `verify_distance=0.30`，却不能重新积累关联。后续多视角只接受 VERIFIED，因此出现“新视角没有确认，也无法进入多视角库”的停滞。

新增默认关闭的 `IdentityConfig.owner_continuity_verify`，仅在 demo 使用的 `reid_owner_trial.yaml` 开启：

- 必须存在新鲜 owner_focus，轨迹为当前仍跟随的轨迹，最近邻身份是已固定主人，且裁剪无其他人体重叠。
- 这种连续跟随中的重新确认使用已有 verify_distance，而非首次/异轨迹的 match_distance；仍需三帧一致、描述子相互接近、身份竞争/互斥和时间检查通过。
- 真正丢失后没有 focus，异位置/新轨迹搜索仍用原 match_distance=0.25，不会因为这项开关直接放宽找回门槛。
- 骨架掩码处理过的重叠裁剪也明确标为 overlapped，禁止借其重新确认连续主人或学习额外视角；原先只将完全拒绝裁剪的 overlap 理由传给关联器。
- 已确认的干净新视角仍经下一次 VERIFIED 才进入额外视角库。无效 Pose、过期结果仍撤回输出并取消旧代次。运动门控、20 秒窗口、三帧/0.4 秒找回条件和遮挡检查不变。
