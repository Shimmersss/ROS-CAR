## 启动准备

现场确认小车静止后，结束原服务，再在终端运行新入口：

```bash
systemctl --user stop roscar-robot.service
cd /home/wheeltec/ROSCAR-demo-20261016
bash scripts/start_demo_trial_onboard.sh
```

入口拒绝与原服务并开，读取板端私有 robot.env，但强制运动关闭及 demo 配置。此入口用于感知和录制准备，不会让小车跟随移动。实际跟随需现场人员另行确认开启运动能力，再按已有模式/epoch 授权流程操作；录制程序不授权、不发布速度、不清除急停。不要直接恢复原服务来尝试运动。

另开终端录制（复用相机 ROS 数据，不打开第二个相机驱动）：

```bash
cd /home/wheeltec/ROSCAR-demo-20261016
bash scripts/record_demo_trial.sh fall-toward-camera-01 --seconds 60 --speech
```

默认 60 秒，范围 10–180 秒。确认 bag 已建立后播报开始，每 30 秒播报进度，结束后检查 bag 元数据及关键话题实际消息数，再播报完成。通过 `/voice/say` 复用唯一播报队列；播报超时记入 speech.log，不中断录制。Ctrl+C 提前结束并收尾。启动要求至少 10 GiB 可用，录制中低于 3 GiB 结束；每个 bag 文件限制约 1 GiB。

输出在 `data/demo-trials/时间-段名/`：`bag/`、`session.json`、`recorder.log`、`speech.log` 和 `bag-info.txt`。保存原始与校正 RGB、深度和内参，人体/延续状态、跌倒告警、主人、目标、里程计、请求速度及最终速度、TF。录制文件保留在车端，不提交 Git。它是 ROS bag，不能直接冒充旧 Mac 格式输入现有离线评分脚本；后续须按原时间戳导出并人工标注。

## 补录顺序

1. 运动关闭：先录 10 秒检查帧、深度和播报，再录正常站立、蹲下、坐地、快速主动躺下、靠近相机和正常出画，每类独立命名，保留前后各 5 秒。
2. 跌倒效果：保持实际机位和 1.3 m 距离，分别录朝车方向、侧向、背向的受控倒地；记录倒地后是否完全出画，采用软垫与现场协助，避免真实摔伤。人体、报警、主人冻结和暂停结果须分别验收。
3. 跟随效果：现场完成运动授权后，再录直行、转弯、站定、近距离走过、遮挡及找回，单段 30–60 秒，记录目标距离误差、丢失和停车时刻。跌倒动作不与未经验证的运动跟随同时测试。
4. 每段补充人员、机位、起始距离、动作时间、预期结果；专门区分坐地/躺下反例和跌倒事件。录制成功不代表检出率、实车制动或跟随验收通过。
