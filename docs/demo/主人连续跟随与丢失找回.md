# Demo 主人连续跟随与丢失找回

2026-10-19 按用户选择准备的新策略：正常阶段靠检测与 VitTrack 保持连续性，ReID 在后台记录主人外观，彻底失去连续性后才用身份找回。**本机代码和验证已完成；按用户“等会一起部署”的要求，本轮没有更新车端。**

## 行为

1. 首次由 `/perception/claim_owner` 显式认领，可以指定画面内任意新鲜 `epoch:track_id`，空 ID 则选中央轨迹。认领后即可在原有运动授权条件下跟随，不必等待 ReID 先确认。
2. ReID 在认领轨迹上用连续三帧已核验身份建立主人绑定。遮挡/重叠、缺证据、陈旧/失配帧打断这一计数。未绑定成功就完全丢失时，需要人工重新认领，不能凭位置猜主人。
3. 正常跟随阶段，ReID 缺结果、暂时匹配到不同身份或在别处报告主人，都不会改变/撤销当前轨迹。VitTrack 与检测冲突时仍可暂停或释放；关闭 ReID 否决不代表 VitTrack 能保证多人身份不交换。
4. 彻底失去当前轨迹/接续后，在原主人保留窗口内扫描当前画面的真实检测。候选必须是同一持久身份，至少连续 **3 个新鲜结果、跨至少 0.4 秒**，才接回新的轨迹；没有“必须回原像素位置”的条件。
5. 同一身份对应多候选、重复身份行、没有匹配、无效/过期/无法精确配帧的结果、超过 0.5 秒的证据间隔，都会阻止或重启确认。重复/倒序结果不累计。候选在证据帧与当前帧都不能与其他人体显著重叠（交叠超过较小框面积的 10%）。
6. demo 强制关闭 `AUTO_LOCK_SINGLE`。保留既有连续丢失 2 秒清轨迹、同一次丢失 5 秒清主人/外观库的边界；过期后等待人工认领，陌生人独自出现也不会自动接替。跌倒冻结仍按原逻辑暂停生命周期时钟。这里没有延长主人等待时间。

## 跟随中会不会补充外观

会。ReID 继续后台运行，保留现有质量门控、同帧 RGB/Pose 配对和 OSNet 模型。`reid_owner_trial.yaml` 的常规库最多 8 个特征；已绑定主人的额外视角最多 24 个。

普通库仅在当前外观核验通过且足够接近时更新；额外视角还必须来自 `owner_focus` 指向的当前跟随轨迹、身份核验通过、没有重叠，并且与已存视角有足够差异。完全丢失后没有当前跟随轨迹，不会把未知候选直接作为主人新视角。主动释放/主人过期会清除旧主人绑定，车端 `forget_released_owner=true` 时同时移除旧库。

这有助于积累转身后的侧面/背面，但受实际模型区分能力、裁剪质量和已存视角限制。仅凭背面或相似衣着不能保证识别正确；本轮没有宣称真人找回率或多人误认率已改善。

## 配置与兼容

| 项目 | 通用默认 | 新 Demo |
|---|---|---|
| `REID_REACQUIRE_ENABLED` | 按入口显式设置 | true |
| `AUTO_LOCK_SINGLE` | 保留通用入口策略 | false |
| `SOT_ENABLED` | 按入口显式设置 | true |
| `reid_reacquire_only_after_loss` | false，保留原 ReID 否决行为 | true |
| `reid_reacquire_confirm_frames` | 2 | 3 |
| `reid_reacquire_min_s` | 0 | 0.4 |

新增策略参数在 `pose_fixed_27cm_demo.yaml`，自定义 `POSE_CONFIG` 时需显式保留。`reid_lock_enabled` 仍关闭；找回使用 `OwnerSelection`，不启用持续依赖 ReID 的身份锁模式。没有更换/下载模型或放宽身份距离门槛。

跟随仍为 1.3 m、目标宽限 0.6 s、仅目标 FAULT 自动恢复，首次运动需显式授权。跌倒立即置零、STOP/ESTOP/其他故障锁存均沿用，外观节点不发布速度。
