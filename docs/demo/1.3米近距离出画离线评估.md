按用户最新选择，`scripts/run_demo.sh` 的默认跟随距离由 1.8 m 改回 **1.3 m**，仍允许显式环境变量覆盖。本轮没有部署或修改板端服务。

用户选择“先做离线对比，按误报结果决定”，因此先评估候选，再决定是否接入运行链。结果：**两类候选均不启用，保留上一轮已验证的跌倒逻辑。** 距离修改已生效于 demo 默认入口，不能把此修改描述为已经解决出画漏检。

## 候选规则与结果

新增离线工具 `scripts/evaluate_demo_blindspot.py`，复用上一轮已验证的同帧合并告警作为基线，核对关键点/高度缓存、标注和时间戳输入指纹。只使用真实框与高度，不补造关键点、框或深度。

候选要求同一轨迹至少三个连续有效测量，在 0.8 秒内身体高度下降 0.3/0.4/0.5 m，框顶同时下移至少 38.4 px，当前高度低于 0.9 m，且框底接近 480 px 图像下沿（距下沿 24/48 px）。上沿、侧沿截断及超过 0.3 秒观测间隔拒绝此证据；倒退时间或 epoch 改变清空历史。

比较两种处理：

- **提前疑似**：上述下坠条件满足就报告疑似。
- **丢人后疑似保持**：上述条件刚成立后 0.3 秒内检测消失，才报告疑似。

候选都最多保持 6 秒，只输出疑似，不把失踪升级为确认。高度恢复到 0.9 m 及以上清除候选。这里只生成离线时间线，不控制跟随或冻结主人。

8 段录像共 20 次跌倒、19 个反例；全部 12 组的合并疑似/确认检出均为 **19/20、19/20**，确认误报均为 **1/19**，没有补回 A2a 的剩余漏检。

| 模式 | 下沿范围 | 疑似误报动作数：降幅 0.3 / 0.4 / 0.5 m | 未标注疑似上升沿：同序 |
|---|---|---|---|
| 原基线 | — | 1 | 0 |
| 丢人后保持 | 24 px | 1 / 1 / 1 | 0 / 0 / 0 |
| 丢人后保持 | 48 px | 1 / 1 / 1 | 0 / 0 / 0 |
| 提前疑似 | 24 px | 3 / 2 / 2 | 0 / 0 / 0 |
| 提前疑似 | 48 px | 8 / 7 / 6 | 2 / 2 / 0 |

提前疑似可以让一些事件更早提醒，但在 A4 的快速坐地/主动躺下、A5 的坐地反例中增加误报。24 px 丢人候选完全没有触发，不能把“无误报”当作有效性证据；48 px 丢人候选只覆盖 A2a/A3 已被基线检出的事件，没有新增检出收益。因此两类候选均保留在离线工具内，不修改运行时告警、运动或主人状态。

这批录像不是 1.3 m 运动跟随时的专门盲区验收。未拍到身体且出画前没有充分下坠证据时，现有相机无法提供确认依据；下一轮需要在实际 1.3 m 距离补录朝车跌倒、蹲下、坐地、近距离走过和正常出画，包含下坠前到出画后的完整过程，再比较下沿候选。

## 复现

先确保已生成 `evaluate_demo_fall_refinement.py` 的 `validated` 基线，然后运行：

```bash
/Users/shimmer/Documents/ChatGPT/ROSCAR/.venv/bin/python \
  scripts/evaluate_demo_blindspot.py \
  --source-root /Users/shimmer/Documents/ChatGPT/ROSCAR \
  --baseline artifacts/demo-fall-refinement/validated \
  --output artifacts/demo-blindspot
```

输出为每组汇总、逐事件比较、候选时间线和输入 SHA256。测试覆盖单纯丢人不触发、必须测得下坠、截断拒绝、epoch/时间断裂清理、有界保持且永不确认，以及 demo 默认 1.3 m。没有本轮 ROS 编译、车端部署或实车验收。
