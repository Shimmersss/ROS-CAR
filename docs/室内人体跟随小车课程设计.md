# 基于 RGB-D 视觉与目标跟踪的室内人体跟随小车课程设计

> 文档性质：课程设计方案与阶段性总结。日期：2026 年 9 月 14 日。本文区分已有源码、已验证框架与拟实现算法；实验部分为设计方法，不包含虚构的实测结果。

## 摘要

本课题面向室内陪行、物品运输等场景，设计一种基于 RGB-D 相机和嵌入式计算平台的人体跟随系统。系统以 Orin Nano Super 8GB 为上位机，利用彩色图像识别人、利用深度图确定空间位置，通过多目标跟踪维持目标关联，再经过锁定决策、异常值剔除和时序滤波，形成稳定的距离与方向信息。后续由控制模块生成速度指令，下位机执行电机控制。课题比较 Astra 骨架 SDK 和 YOLO11n + ByteTrack 两条路线，重点研究多人干扰、目标遮挡、深度噪声以及控制延迟等问题，并使用 ROS 2、Foxglove 和 SSH 完成模块通信与远程调试。当前已建立软件框架，真实相机感知与车辆闭环仍待实施。

**关键词：** 人体识别；目标锁定；RGB-D；ByteTrack；卡尔曼滤波；视觉跟随；ROS 2。

## 1. 设计目标与总体结构

系统需要回答四个问题：画面中谁是人、应该跟随谁、目标位于何处、小车如何运动。识别提供类别与位置，跟踪建立跨帧关联，锁定决定服务对象，测距提供空间信息，控制完成车辆响应。这些环节互相配合，但职责不能混淆，例如检测到一个人并不意味着应该立即跟随。

硬件计划包括 Orin Nano Super 8GB、RGB-D 深度相机、底盘控制器和移动底盘。用户最初称相机为 Astra Pro，现有商品资料还涉及其他型号，因此到手型号、驱动兼容性和骨架授权需要核对，不能直接假定全部功能可用。当前先验证感知，暂不连接车辆运动。

```text
彩色图像 + 深度图 + 相机内参
                ↓
       人体检测或 SDK 骨架
                ↓
       跨帧跟踪与目标锁定
                ↓
     深度采样、坐标变换、滤波
                ↓
        目标状态与调试展示
                ↓ 后续阶段
     跟随控制 → 串口 → 下位机
```

软件采用 ROS 2 Humble 分模块设计。感知模块输出带时间戳的目标状态，控制模块独立消费这些状态。相机、算法和控制不应相互阻塞，以便分别测试并替换实现。

## 2. 人体感知的两条路线

### 2.1 方案 A：SDK 骨架与姿势锁定

该方案通过厂商 SDK 获得人体 ID、关节点、跟踪状态和人体质心。应用程序根据肩、肘、髋等关节点的相对位置判断动作，例如使用双手叉腰作为选择目标的触发条件。锁定后持续读取对应人体的位置，供测距和跟随模块使用。

已有厂商应用源码包含姿势锁定、质心读取、平均 RGB 颜色辅助恢复 ID 和简化 PD 控制。骨架输出及其调用逻辑可以阅读，但附带 SDK 核心以二进制库提供，无法据此确认内部网络结构或滤波算法。平均颜色恢复属于简单外观匹配，容易受光照和相似服装干扰，不能等同于成熟的行人重识别。

这条路线有利于实现手势交互，但依赖具体设备、运行库和授权。它适合作为对照实验，首先验证 SDK 能否在目标设备上持续输出有效骨架，而不是直接把附带代码视为已经运行成功。

### 2.2 方案 B：YOLO11n 与深度融合

YOLO 检测器处理 RGB 图像，输出人体框、类别和置信度。YOLO11n 可作为初始候选，随后依据实测速度和漏检情况决定是否更换模型或输入尺寸。现有源码附带该权重，但尚未接通人体推理，不能预先宣称已达到某个帧率。

仅有检测框不能回答“是不是上一帧那个人”，因此还要接入跟踪器。对于基础跟随任务，人体检测配合深度即可建立闭环；若需要手势选择或更准确的躯干区域，再增加 Pose。姿态估计提供关键点，实例分割提供像素区域，两者都不能自动替代目标身份管理。

## 3. 跨帧跟踪与目标锁定

ByteTrack 将已有轨迹与当前检测结果进行关联。其特点是分阶段利用高置信度和低置信度检测，尝试恢复被遮挡后置信度下降的目标，从而减少轨迹中断。其运动模型和关联机制有助于跨帧保持编号，但不保证人在离开画面很久后仍获得原编号。[参考：ByteTrack 论文](https://arxiv.org/abs/2110.06864)

锁定应在跟踪之上增加独立决策。课设可先采用人工选择目标 ID；也可让用户进入画面中央并停留一定时间，或使用指定手势确认。候选人应连续多帧满足条件，再进入锁定状态，避免把偶然检测当作目标。锁定后不应因为另一个人更近或置信度更高而立即切换。

建议设计 SEARCHING、LOCKED、TEMP_LOST 和 WAIT_CONFIRM 四种内部状态：搜索时等待选择；锁定时输出有效观测；短时丢失时保留身份线索；持续丢失或出现歧义时等待确认。它们是拟设计的决策状态，需映射到现有 TargetState 的 SEARCHING、TRACKING、LOST 等输出，不能直接当作已经实现的枚举。

短时遮挡可结合轨迹预测、位置连续性和外观特征恢复。恢复候选需要同时满足时间、空间及外观约束；不能只选择最近的人。多人交叉造成身份交换时，宁可停止并重新确认。ReID 可作为后续增强，但仍需评估相似服装、背面和光照变化造成的误匹配。Ultralytics 提供跟踪调用接口，持续视频流还需要正确保持跟踪状态。[参考：官方跟踪文档](https://docs.ultralytics.com/modes/track/)

## 4. 深度测距与坐标转换

RGB 图像中的一个像素不一定对应原始深度图的同一像素，因为两个成像传感器可能存在位置和内参差异。测距前必须确认深度和彩色图像配准，并控制采集时间差。把同分辨率误认为已对齐，会使人体框采到背景距离。厂商 Astra ROS 驱动提供相关配准参数，但实际支持情况仍需结合设备检查。[参考：Astra 驱动说明](https://github.com/orbbec/ros2_astra_camera/blob/master/README.MD)

深度提取不宜只读检测框中心一个点，也不宜直接平均整个人体框。单点容易落在孔洞上，整框又可能包含墙面和地板。初版可从框内较小的躯干区域采样，剔除零值、非有限值和超出有效量程的值，再计算中位数。如果出现明显的前后景分层，可根据上一时刻距离选择一致的深度簇，并检查有效像素比例。阈值应根据相机和实验标定。

对于已经校正、配准且采用光轴深度的图像，像素位置为 `(u,v)`，深度为 `Z`，内参为 `fx、fy、cx、cy`，可反投影得到：

```text
X = (u - cx) × Z / fx
Y = (v - cy) × Z / fy
```

深度单位必须统一为米，不能凭数据类型猜测。区域统计深度应搭配合理的代表像素，或者对有效像素逐点反投影后求稳健中心。

相机光学坐标通常是 X 向右、Y 向下、Z 向前。当前接口中的 `sqrt(X²+Z²)` 表示光学 XZ 平面距离，不应在相机俯仰安装时直接称为地面距离。车辆控制应通过标定外参转换到车体坐标，再用 `d=sqrt(x²+y²)`、`θ=atan2(y,x)` 计算水平距离和偏角。

## 5. 滤波方法及其分工

### 5.1 空间滤波与时间平滑

空间中位数主要处理单帧深度中的离群点；时间滤波处理连续观测的抖动。简单实现可采用指数平滑：

```text
p_filtered(k) = α × p_measured(k) + (1-α) × p_filtered(k-1)
```

较大的 α 响应快，较小的 α 更平滑但滞后更明显。无效深度应标记为缺测，不能填零后参与平均，否则会产生目标突然贴近的假象。滤波也不能消除错误锁定或配准错误，因此数据有效性检查应放在滤波之前。

### 5.2 卡尔曼滤波

卡尔曼滤波使用运动模型预测状态，再结合新观测进行修正。以平面位置为例，可定义状态 `s=[x,y,vx,vy]ᵀ`，采用短时间内匀速的近似：

```text
s_pre = F(Δt) × s_prev
P_pre = F × P_prev × Fᵀ + Q
K = P_pre × Hᵀ × (H × P_pre × Hᵀ + R)⁻¹
s_new = s_pre + K × (z - H × s_pre)
P_new = (I - K × H) × P_pre
```

其中 F 根据实际帧间隔传播位置，H 提取可观测的位置分量，P 表示估计不确定性，Q 表示运动模型误差，R 表示测量误差。测量越不稳定，应给予越低的信任；人体急转弯时，匀速模型也可能失效。异常值可通过创新残差及其协方差进行门限判断，而不是全部强行融合。

本项目需要区分三类滤波：ByteTrack 内置卡尔曼处理图像检测框状态；拟新增的位置滤波处理深度反投影后的空间观测；整车 EKF 则处理小车自身定位。三者对象不同，不能认为接入 ByteTrack 就已经完成深度融合，也不能确认闭源骨架 SDK 内部使用了哪一种滤波。

小车转动时，即使人站着不动，相机中的目标位置也会变化。若直接在移动相机坐标中采用匀速模型，状态速度包含相对运动。初期可将其作为短时平滑近似；需要估计人体世界速度时，应结合可靠的车体位姿变换到稳定坐标系，并考虑自身定位误差。

## 6. 跟随控制与状态保护

设期望跟随距离为 `d₀`，距离误差 `e_d=d-d₀`，目标偏角为 θ。课设初期可采用比例控制：

```text
v = limit(Kd × e_d, 0, vmax)
ω = limit(Kθ × θ, -ωmax, ωmax)
```

这里假设车体系 X 向前、Y 向左，正角速度对应左转。初版设计不主动倒车，距离过近时停车；偏角较大时先减速转向，避免一边快速前进一边寻找目标。差速、麦克纳姆轮和阿克曼底盘的可执行运动不同，具体控制映射需等待车型确认。

为减少抖动，应设置距离和角度死区、最大速度及加速度约束。若增加微分项，应使用实际时间间隔并处理测量噪声；现有厂商代码属于简化 PD，不能直接视为完整、已调好的 PID。外环视觉控制负责期望车速，下位机负责更高频的电机闭环。

目标丢失、观测过期或深度无效时，应停止产生前进请求。短时保留预测轨迹仅服务于身份恢复，不代表可以继续盲目前进。还需要独立障碍物检测、急停和下位机指令超时停车；“能够看到目标”不代表目标与车辆之间没有障碍。

## 7. 通信与调试设计

Nano 负责图像和算法处理，下位机只接收速度等控制量。已迁入厂商串口源码，标准控制帧 11 字节、基础反馈帧 24 字节，采用帧头、帧尾和异或校验。反馈包含底盘速度、IMU 原始数据和电压，图像与骨架不通过该串口传输。该代码当前被 COLCON_IGNORE 跳过，未启动，实物协议兼容性待确认。

ROS 消息应携带坐标系、观测时间、发布时刻、来源、目标 ID、有效性和模拟标志。数据年龄用于判断新鲜度，防止系统把重复发布的旧位置当作新观测。Foxglove 计划展示图像、检测框、目标轨迹、原始与滤波距离曲线、状态和处理延迟；SSH 用于启动节点、查看日志及同步代码。展示面板不替代算法节点的数据发布。

## 8. 实验方案与评价指标

实验按“离线感知—固定相机—移动相机—车辆闭环”逐级推进。每次保存参数、模型版本、录制数据和设备状态，使不同算法可以在同一输入上比较。

| 实验 | 主要观察指标 |
|---|---|
| 不同距离、姿势与光照下检测 | 漏检、误检、处理帧率 |
| 多人交叉与相似服装 | ID 切换次数、误锁次数 |
| 短时遮挡与离开画面 | 恢复时间、是否错误换人 |
| 已知距离的静态测距 | 平均绝对误差、有效深度比例 |
| 原始值与滤波值对比 | 静态标准差、动态滞后、异常跳变 |
| 后续直行、转弯和停止跟随 | 距离误差、超调、停止响应 |

测距误差可用 `MAE=Σ|d_est-d_ref|/N`，跟随误差可用距离 RMSE。静态抖动应在目标与相机均静止时测量；动态滞后则通过受控运动单独评估，避免以过度平滑换取看似优秀的曲线。建议进行无滤波、指数平滑、卡尔曼三组消融实验，并比较单点深度和区域稳健深度。所有指标须注明条件，当前不填入未经测量的数值。

### 8.1 实时性与误差分析

系统延迟不仅来自神经网络，还包括相机曝光、图像传输、排队、深度匹配和控制周期。记录采集时间与各阶段完成时间，才能判断瓶颈。处理速度低于输入帧率时，应限制队列长度，优先处理较新的完整观测，避免小车根据积压画面行动。模型输入分辨率、推理精度和压缩传输需要分别评估，不能只看单次推理耗时。

误差分析应同时考虑检测框偏移、深度孔洞、相机安装外参误差和身份关联错误。前几类通常表现为位置偏差或噪声，身份错误则可能使目标位置整体跳转。因此，位置滤波只在身份和测量可信的前提下使用；锁定对象变化时，应重新初始化相应滤波状态，避免把两个人的位置混合成一条虚假轨迹。

## 9. 当前成果与后续安排

目前已建立公共目标消息、A/B 入口、模拟数据演示和相关文档。方案 A 已在 Jetson 接入真实 `/bodylist`，完成叉腰锁定、质心测距、状态机、掩码和 Foxglove 真人验收，并正式接入 `route:=astra`；方案 B 仍为 NOT_READY。串口副本尚未编译或连接硬件。

后续先确认相机及 Jetson 环境，接通 RGB、深度和配准；再实现人体检测、轨迹锁定和稳健测距；随后对比滤波方案并完善 Foxglove 展示；最后才接入底盘控制、障碍检测和实车测试。课设的主要价值在于建立可解释、可验证的完整数据链路，通过实验说明身份关联、测量质量和控制响应之间的关系，而不是仅展示一个能画检测框的程序。
